# 예약 실행 점검 (watchdog)

예약해 둔 무인 작업이 **실제로 돌았는지** 확인하고, 안 돌았거나 실패했으면 사람에게 알린다.

전원이 꺼져 있던 회차는 윈도 작업 스케줄러가 켠 뒤 따라 실행해 준다(`StartWhenAvailable`). 문제는 **켜져 있는데도 빠지거나 중간에 죽는 경우**다 — 아무도 모른 채 지나간다. 2026-09-15 이후 50일 동안 eCoDY ECM 모니터링이 멈춰 있던 것을 아무도 몰랐던 일이 그래서 생겼다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `check_runs.ps1` | 점검기 본체. 작업 스케줄러가 평일 10:00 에 부른다 |
| `register_task.ps1` | 그 10:00 작업을 등록하는 설치용. PC 를 새로 깔았을 때만 다시 쓴다 |

로그·보고서는 저장소가 아니라 작업 폴더 `D:\Ljindong\automation\watchdog\` 에 쌓인다. 프로그램은 저장소, 기록은 작업 폴더 — `run.cmd` 와 같은 규칙이다.

## 설치

```
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Ljindong\skills-repo\watchdog\register_task.ps1"
```

작업 이름 `예약 실행 점검`, 평일 10:00, 놓치면 따라 실행, 실행 제한 10분.

## 판정

대상 작업의 로그에서 `===== 날짜 시각 RUN START =====` 과 `===== EXIT CODE n =====` 을 찾아 가린다.

| 판정 | 뜻 | 알림 |
| --- | --- | --- |
| 성공 | `EXIT CODE 0` | 없음 |
| 실행 중 | 시작했고 작업이 아직 `Running` | 없음 |
| 건너뜀 | 주말 / 판정 시각 전 / 오늘 예약을 등록·변경했음 | 없음 |
| **안 돌았음** | 예정 시각이 지났는데 오늘 기록이 없음 | 있음 |
| **중간에 죽음** | 시작 기록은 있는데 종료 기록이 없고 작업도 멈춤 | 있음 |
| **실패** | `EXIT CODE` 가 0 이 아님 (로그에서 사유를 꺼내 붙인다) | 있음 |

알림은 윈도 알림 → 비프 3회 → **보고서를 메모장으로 띄움** 세 겹이고, **하루 한 번만** 띄운다. 종료 코드는 문제가 있으면 2.

## 왜 Claude 를 쓰지 않는가

감시 장치가 감시 대상과 같은 이유로 죽으면 의미가 없다. 2026-11-05 에 Redmine 작업이 `API Error: Can't reach the API server (ENOTFOUND)` 로 죽었는데, 점검기가 Claude 를 쓴다면 같은 날 같은 이유로 못 돌았을 것이다. 그래서 순수 PowerShell 로만 짰다.

## 점검 대상 늘리기

`check_runs.ps1` 의 `$Jobs` 에 블록을 하나 더 넣으면 된다. Redmine 일일 대시보드 블록이 주석으로 들어 있다 — **eCoDY 쪽이 안정된 뒤 되살릴 예정이고 폐기가 아니다.** 되살릴 때 예약 시각(`Due`)을 그때 값으로 맞춘다.

## 실측 메모 (2026-11-05)

- 머리글을 느슨하게(`-like '*RUN START*'`) 찾으면 로그에 적어 둔 메모까지 실행 기록으로 오인한다. 정규식으로 모양을 정확히 맞춰야 한다.
- 예약을 건 당일은 시각이 이미 지나 기록이 없는 것이 당연하다. 트리거 시작일이 오늘이면 판정하지 않는다.
- `.ps1` 은 **UTF-8 BOM** 으로 저장해야 한다. BOM 이 없으면 PowerShell 5.1 이 ANSI(949)로 읽어 한글이 깨진다.
