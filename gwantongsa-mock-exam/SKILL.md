# 관통사 모의고사 생성기

관광통역안내사 필기 대비 모의고사 한 회분(국사 25문항 + 관광자원해설 25문항, 4지선다)을 생성 → 검증 → 인쇄용 PDF 전달까지 수행한다. **메일 발송은 하지 않는다.**

시험 응시자는 사용자(진스)의 연인(그림작가)이며, 시험일은 2026-09-05다. 요청 시 남은 날짜(D-day)를 언급해 주면 좋다.

**근거 제일 원칙**: 모든 문항·해설은 추정이 아닌 **검증 가능한 역사적·법적 근거**로 작성한다. 공신력 있는 출처(국사편찬위원회 우리역사넷, 한국민족문화대백과사전, 국가유산청, 법제처 국가법령정보센터, 유네스코 공식 목록, Q-net 기출)로 확인되지 않는 사실은 문제에 쓰지 않는다. 그럴듯한 기억으로 연도·명칭을 적는 것이 이 스킬의 가장 큰 실패 모드다 — 조금이라도 애매하면 검색으로 확정하고, 확정 못 하면 그 소재를 버린다.

## 왜 이 절차인가

이 스킬의 존재 이유는 세 가지 실패를 막는 것이다: ① 낡은 법령/오류 사실로 만든 **오답 문제**(공부에 해로움), ② 매번 비슷한 소재의 **재탕 문제**(학습 효과 없음), ③ 정답 번호 쏠림·오타 같은 **품질 결함**. 아래 절차의 각 단계는 이 셋 중 하나를 막기 위해 존재하므로 건너뛰지 마라.

## 절차

### 0. 준비

- `references/history-guide.md`(국사 출제 규칙)와 `references/tourism-guide.md`(관광자원 출제 규칙 + 최신화 체크리스트)를 **둘 다 읽는다**.
- 의존성 확인: `python3 -c "import weasyprint"` — 없으면 `pip install weasyprint --break-system-packages`.

### 1. 출제 이력 로드 (중복 방지)

이력은 사용자의 Google Drive **"관통사 모의고사" 폴더**(ID: `13vrx9EYVCYTEQCxKndhTHvd0OxsP9y8L`)에 `이력_제N회_날짜.txt` 파일들로 저장되어 있다. (이 계정은 memory 기능이 꺼져 있으므로 memory 도구를 쓰지 마라.)

- `mcp__Google_Drive__search_files`로 위 폴더에서 `이력_` 파일들을 찾아 `read_file_content`로 전부 읽는다.
- 형식: 첫 줄 `회차<TAB>N<TAB>날짜`, 이후 한 줄에 `날짜<TAB>과목<TAB>키워드1,키워드2,...` (문항당 한 줄)
- 모든 이력 파일의 내용을 합쳐 작업 디렉토리에 `history.txt`로 저장한다 (검증 스크립트가 사용). 이번 회차 = 이력상 최대 회차 + 1.
- 폴더나 파일이 없으면 첫 회차로 진행하되 결과 요약에 명시한다.

### 2. 최신 정보 확인 (관광자원 필수)

`tourism-guide.md`의 "생성 전 필수 최신화 체크" 항목을 웹 검색으로 확인한다. 특히 유네스코 등재 목록, 국가유산 체제, 국립공원 지정 현황, 관광진흥법 개정. 국사도 확신이 서지 않는 연도·사실은 검색으로 확정한다. 최근 기출 소재도 검색해(예: "관광통역안내사 2025 국사 기출") 이력에 없는 신선한 소재를 고른다.

### 3. 시험지 JSON 작성

아래 스키마로 `exam.json`을 작성한다. 문항 작성 규칙은 두 가이드 문서를 따른다.

```json
{
  "title": "관광통역안내사 모의고사",
  "round": 3,
  "date": "2026-08-02",
  "subjects": [
    {
      "name": "국사",
      "questions": [
        {
          "no": 1,
          "era": "고려",
          "qtype": "배열",
          "question": "(ㄱ)~(ㄹ)의 사건을 시대순으로 바르게 배열한 것은?",
          "passage": "(ㄱ) 노비안검법 실시\n(ㄴ) ...",
          "choices": ["(ㄱ)-(ㄴ)-(ㄷ)-(ㄹ)", "...", "...", "..."],
          "answer": 2,
          "explanation": "40자 이상의 상세 해설. 정답 근거가 되는 사실들의 연결 고리와 연도·왕·시대를 명시.",
          "wrong": ["① ~는 ~시대의 사실이다.", "..."],
          "keywords": ["노비안검법", "광종", "고려 초기 개혁"]
        }
      ]
    },
    { "name": "관광자원해설", "questions": [ { "no": 26, "category": "유네스코", "...": "..." } ] }
  ]
}
```

핵심 규칙 (스크립트가 강제 검사한다):
- 국사 1~25번, 관광자원해설 26~50번. 선택지 4개(번호 기호 ①② 없이 텍스트만 — 템플릿이 붙인다).
- 국사: 선사 1~2, 근현대 2~4(**4 초과 절대 금지**), 배열형 5~8문항, 전 문항 심화형(단답 금지).
- `round`는 이력상 마지막 회차 + 1.
- **정답 번호는 의도적으로 분산**: 과목별로 각 번호 4~9회, 같은 번호 4연속 금지. 작성 후 몰아서 배치하지 말고 처음부터 섞어 써라.
- `keywords`의 첫 번째 항목은 그 문항의 핵심 주제 1개(이력 대조 기준이 된다).

### 4. 자동 검증

```bash
python3 scripts/validate_exam.py exam.json --history history.txt
```

`RESULT: PASS`가 나올 때까지 수정한다. WARN(이력 중복 의심)이 나온 문항은 각각 판단하되, 같은 소재의 재탕이면 반드시 주제를 교체한다.

### 5. 사실 검증 패스 (오답·오타 제로 게이트)

자동 검증과 별개로, **전 문항을 새로운 눈으로 재검토**한다. 이 단계가 이 스킬의 품질을 결정한다.

- 각 문항에 대해: 정답이 정말 맞는가? 오답 중에 실은 맞는 것이 섞여 있지 않은가(복수 정답 사고)? 연도·인명·지명·한자어 오타는 없는가?
- 서브에이전트(Agent 도구)를 쓸 수 있으면 "이 시험지에서 사실 오류·복수 정답·오타를 찾아 반박하라"는 독립 검증자를 1개 이상 띄워 교차 검증한다. 없으면 본인이 문항 순서를 거꾸로 훑으며 재검토한다.
- 조금이라도 확신이 없는 사실은 웹 검색으로 확정하고, 확정이 안 되면 **그 문항을 버리고 새 문항으로 교체**한다(교체 후 4단계 재실행).

### 6. PDF 생성

```bash
python3 scripts/build_pdf.py exam.json 출력디렉토리
```

문제지·해설지 두 PDF가 생성된다(A4, 2단, 8pt, 여백 6mm — 사용자가 지정한 인쇄 절약 규격이므로 임의로 바꾸지 마라). 생성 후 PDF를 Read 도구로 열어 깨진 글자·레이아웃 이상이 없는지 눈으로 확인한다.

### 7. 전달 (PDF는 채팅 전달 → 사용자가 직접 Drive 저장)

**메일은 보내지 않는다. PDF를 Drive에 업로드하려고 시도하지도 마라.**

PDF를 폴더에 넣는 일은 **사용자가 채팅의 파일에서 "Google Drive에 저장"을 눌러** 직접 한다. 이것이 레이아웃이 온전한 PDF를 폴더에 넣는 유일한 경로다. 모델이 직접 올릴 수 없는 이유는 두 가지이며 우회 시도는 전부 실패한다:
- `create_file`의 `base64Content`는 **모델이 base64 문자열을 직접 출력**해야 한다. 실측 결과 PDF 한 개가 약 235KB → base64 32만 자(8만 토큰 초과)로 출력 한도를 넘겨 잘리고, 한 글자만 어긋나도 파일이 깨진다.
- 컨테이너에서 Drive API를 직접 호출하는 것은 네트워크 허용 도메인에 googleapis.com이 없어 차단된다.

절차:

1. 두 PDF를 파일 전달 도구(present_files / SendUserFile)로 사용자에게 전달한다.
2. 전달 후 한 줄로 안내한다: "저장 버튼을 누르면 Drive 홈에 떨어지니 **관통사 모의고사** 폴더로 옮겨주세요." (저장 위치를 지정하는 기능은 모델 쪽에 없다 — 이동은 사용자 몫이므로 매번 짧게 안내한다.)
3. `mcp__Google_Drive__create_file`로 **이력 파일 하나만** 폴더에 업로드한다 (`textContent` + `contentMimeType: text/plain`):
   - `이력_제N회_날짜.txt` (8단계 형식)
   **업로드 위치 검증 필수**: `parentId`에 `13vrx9EYVCYTEQCxKndhTHvd0OxsP9y8L`를 반드시 지정하고, 호출 결과의 `parentId`가 이 값과 일치하는지 확인하라. 빠뜨리면 Drive 홈에 떨어져 다음 회차 중복 방지가 깨진다. 잘못 생성됐으면 올바른 parentId로 다시 올리고, 잘못된 파일명을 결과 요약에 남겨 사용자가 지울 수 있게 하라.
4. Drive에 올리는 파일은 이력 txt **하나뿐**이다. PDF·HTML은 어떤 형태로도 MCP로 업로드하지 마라. Gmail 도구도 쓰지 않는다.
5. Drive 도구가 세션에 없으면 1~2번만 수행하고, 결과 요약에 "Drive 미연결 — 이력 미기록(다음 회차 중복 방지에 공백 발생)"을 명시한다.

### 8. 이력 기록

7-3단계에서 올리는 `이력_제N회_날짜.txt`가 이력 기록이다. 형식:

```
회차	N	2026-08-03
2026-08-03	국사	노비안검법,광종,고려 초기 개혁
2026-08-03	관광자원해설	종묘,유네스코 세계유산,제례
```

첫 줄에 회차, 이후 문항당 한 줄로 3단계의 keywords를 그대로 기록한다. 이 파일이 다음 회차의 중복 방지 기준이 되므로 절대 빠뜨리지 마라.

### 9. 결과 보고

사용자에게 간단히 보고: 회차, 국사 시대 분포, 배열형 문항 수, 관광자원 영역 분포, 정답 분포, 반영한 최신 법령/등재 사항, 검증에서 교체한 문항 수.

## 무인(예약) 실행 모드

이 스킬은 매일 새벽 예약 작업(scheduled task)으로도 실행된다. 예약 실행이거나 사용자가 자리에 없다고 판단되면:

- 질문(AskUserQuestion)으로 멈추지 말고 기본값으로 진행한다: 국사+관광자원 한 회분, 회차는 Drive 이력의 마지막 회차+1.
- PDF는 채팅에 전달만 되고 Drive 저장은 사용자가 나중에 직접 한다(무인 실행이라 아무도 저장 버튼을 누르지 않는 것이 정상이다). 이력 txt 업로드는 무인이라도 반드시 수행한다.
- Google Drive 도구가 세션에 없으면: 이력 없이 진행하고(새로운 소재 우선), PDF 파일 전달만 한 뒤 결과 요약에 "Drive 미연결 — 이력 미접근·미기록"을 명시한다.
- 검증 단계는 무인이라도 절대 생략하지 않는다 — 품질 게이트가 이 스킬의 존재 이유다.

## 부분 요청 대응

- "국사만 내줘" → 국사 25문항만 생성(관광자원 섹션 생략). validate는 실패하니 `--history`만 참고하고 구조 검사 FAIL 중 관광자원 관련은 무시한다.
- "10문제만" 같은 축소 요청 → 시대 배분을 비율대로 축소(선사 최대 1, 근현대 최대 2, 배열형 최소 2~3).
- 난이도 조정 요청("더 어렵게") → 배열형·사이 끼워넣기형 비중을 올리고 매력적 오답을 강화한다.
