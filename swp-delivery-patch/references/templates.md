# 양식

## 1. Redmine 일감 본문

```
## 1. 목적

[R44][<차종>/<제어기>][FBL][V<x>][APP][V<y>] Delivery_Patch(#<원일감> / eCoDY-IMS <IMS키>)를 <차종> 라인에 적용한다.
직전 적용 건 #<직전일감>(<버전>)에 이어서 하는 작업이다.
근거는 <수평전개 IMS키> 이며, <차종> 은 <적용 사유> 로 적용 대상이다(<회신 날짜>).

- FBL 저장소 : <URL> / 작업 브랜치 : <브랜치> (기준 커밋 <해시>) / PR 대상 : <브랜치>
- FBL 기존 SWP : <e_..._fbl-vX>
- APP 저장소 : <URL> / 작업 브랜치 : <브랜치> / PR 대상 : <브랜치>
- APP 기존 SWP : <e_..._app-vY>
- 패치 파일 : <파일명> (<날짜> 배포, 크기 — 유효본 판정 근거)

### 1.1 진행 순서
(FBL/APP 순서, 중간 조합으로 하는 검증)

## 2. 업무 내용
### 2.1 적용 모듈        (코드블록: 모듈  old -> new)
### 2.2 설정 변경        (IMS 안내 항목, IM 근거)
### 2.3 IA / VC         (항목별 현재 충족 여부)
### 2.4 참고·필수 아님 항목 (반영 여부 판단)
### 2.5 이전 회차 누락 반영
### 2.6 HAE 확인 필요

## 3. 검증 계획
(빌드 / 실기 / 패치 고유 시험 / H-OTA / 결과 보고서)

## 4. 참고 사항
(원 일감, 직전·선행 일감, IMS, ECM 가이드, 정리 문서 링크)

## 검색 태그
[할일] [Delivery_Patch] [SWP] [FBL] [APP] [<모듈>] [<차종>]
```

## 2. Redmine 코멘트 — 패치 작업 결과 (S11)

등록 전 **원문 전체**를 사용자에게 보여 준다.

```
# <APP|FBL> V<x> 패치 작업 — HAE 요청사항과 <차종> 처리 결과

## 1. HAE 패치 요청 (eCoDY-IMS <키>)
- 배경 : <수평전개 키> — <결함 요약 1~2줄>, <차종> 적용 사유
- 배포 파일 : <유효본>, (재배포 시) 이전본 미사용 근거 — CRC 대조 결과
- 설정변경 안내 (<날짜> 개정) : 항목 나열, harmonize <모듈>

## 2. 요청별 처리 결과

| HAE 요청 | <차종> 이전 상태 | 처리 (파일) | 확인 근거 |
|---|---|---|---|
| ... | ... | ... | ... |

적용 제외 (사유)
- ...

기타
- 산출물명, ReleaseNote / ModuleList

## 3. 빌드 결과
- 커밋 <해시> → Jenkins <Job> #<n> <결과> (Auto commit <해시>)
- Generate : 생성기 Error 0 (Warning n, 직전 #m 은 k), 신규 Validation 에러 없음
- Rte Validation : … — #m 과 동일, SAFERTE_ERR 0
- 산출물 : <이름>
- 메모리 (map 섹션 합계, 직전 대비)
  ```
  RAM  a -> b Byte (+c)  원인 섹션
  ROM  a -> b Byte (+c)  원인 섹션
  ```

## 4. 남은 작업
- 실기 검증 …, ALL 빌드, PR, (FBL/APP 짝) 별도 진행
- 상세 분석 : <Confluence URL>
```

표 작성 수준: 열 4개, 칸마다 한 줄. XML 경로 전체·모듈 소스 파일 목록은 넣지 않고 커밋 해시로 대신한다.

다른 코멘트(실기 확인, H-OTA 결과)는 조건(코드블록) → 결과 표 → 판정 → 결과 파일 위치 순으로 쓴다.

## 3. IMS 질문 댓글 (S7)

```
<담당자 멘션>

<프로젝트(차종/제어기)> <FBL|APP> V<x> 패치 적용 중 확인 부탁드립니다.

1. <항목 이름>
- 당사 현황 : <현재 설정·구성, 확인 방법>
- HAE 안내 / 배포본 : <안내 문구 또는 참고 설정 값, 날짜>
- 질문 : <예/아니오 또는 선택지로 답할 수 있게>

2. ...

(첨부 / 캡처 : <있으면>)
```

예:
```
[~배포담당]

HE1i PSU FBL V3.0.19 패치 적용 중 확인 부탁드립니다.

1. IA-092 GptChannel for Fota
- 당사 현황 : GptChannelConfiguration_Fota 를 TCPWM_0_18 / CLOCKS18(5000Hz, 16bit)로 이미 구성해 사용 중
- HAE 안내 / 배포본 : VC 참고 파일(09-10)은 TCPWM_0_54 / Divider 6 = 16000 으로 변경
- 질문 : 기존 채널 유지로 IA-092 를 충족하는지, TCPWM_0_54 로 변경이 필요한지
```

## 4. 패치 커밋 메시지

```
[<제어기>][<차종>] SWP 모듈 패치 적용 (<APP|FBL> : V<x>)

#<일감> [R44][<차종>/<제어기>][...] Delivery_Patch (#<원일감> / <IMS키>)

- <모듈> <old> -> <new> (<근거>, <배포본> 폴더 교체)
- <파일> : <변경 요약>
- <파일> : <변경 요약> (<적용 제외 항목과 사유>)
- 산출물명 <이름>, ReleaseNote / ModuleList v<x> 추가
- 참조 : <배포본, 이전본 미사용 여부>
```
제목을 Hook 동작 단어(Rebuild 등) 하나로 쓰지 않는다. 커밋 꼬리말은 세션 규칙을 따른다.

## 5. Confluence 일감 페이지 골격

confluence-writing 규약(H3 시작, html + data-colwidth 표)으로:

```
요약 문단 (무엇을, 어디까지 했는지)
■ 일감 개요 (표)
■ 패치의 출발점 — 수평전개 (결함 표, 차종 적용 의미)
■ eCoDY-IMS 경과 (날짜 코드블록, 재배포·개정 표시)
■ FBL / APP 항목별 현황 (판정표)
■ eCoDY-ECM 가이드 확인 결과
■ 적용 순서 (FBL/APP 조합)
■ 검증 계획 / 실기 결과
■ HAE 확인 필요
■ 남은 조치 (주체 / 할 일 / 상태)
■ 참고
📌 이 문서의 범위 (근거 자료와 기준 시점)
```
