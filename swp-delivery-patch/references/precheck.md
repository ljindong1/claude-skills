# 사전 점검과 판단 경로 (P 단계)

새 패치는 매번 모듈·버전·안내가 다르다. 그래도 일이 꼬이는 방식은 반복된다. 2025~2026 PSU·PE/PWSW·TPMS 패치 티켓 15건에서 당사 담당자가 HAE 에 한 질문 약 100건을 분류해 보면, 대부분은 아래 넷 중 하나였다.

- 가이드 링크가 열리지 않거나 가이드가 옮겨짐 → 대부분 다른 곳에 답이 이미 있었다
- 배포본에 가이드에 없는 변경이 있음 → 대부분 "Harmonize 부산물이니 무시"
- 가이드가 당사 구성과 맞지 않음 → HAE 답은 "당사가 X 면 해당 없음" 같은 조건부
- 배포본이 빠졌거나 틀림 → HAE 가 보정본을 다시 올림

그래서 패치마다 **(1) 시작 전에 공통 사전 점검 다섯 가지**를 하고, **(2) 요청 항목마다 답을 어디서 얻을지(판단 경로 A~D)**를 정한다. 판단 경로는 판정표의 한 칸으로 남긴다 — 나중에 누가 봐도 "왜 묻지 않고 적용했는지 / 왜 물었는지 / 왜 보류했는지"를 따라갈 수 있게.

## 1. 판단 경로 A~D

요청 항목(또는 배포본에서 발견한 차이) 하나마다 위에서부터 차례로 따져 처음 맞는 경로를 쓴다.

| 경로 | 조건 | 하는 일 | 끝나는 조건 |
|---|---|---|---|
| **D. 회사 기준 보류** | 양산 SW·OTA 호환이 깨질 수 있다(NvM/Fee 블록 크기·배치, 메모리 맵 고정 영역) / 개발 환경이 바뀐다(컴파일러·툴체인 버전, SRS 고정값) / 양산·양산 임박 차종에 영향 | HAE 답을 기다리지 않고 보류. 사유와 근거를 판정표·Redmine 에 기록하고, 필요하면 IMS 에 "미적용 사유"로 알림 | 회사 판단(사용자 확정) |
| **A. 스스로 확정** | 가이드(IM/IA/SAG)가 명확 + 배포본이 가이드와 같음 + 당사 구성 전제(§2-①)와 맞음 + 3-way 판정이 복사 가능/기존 충족 | 판정대로 적용 | 판정표에 근거 절 번호 |
| **B. 과거 자료 조사** | 가이드 링크 권한 없음 / 배포본에 가이드에 없는 변경 / 같은 모듈을 이전 회차·다른 차종에서 다룬 적 있음 / HAE 답변이 이미 있을 법한 질문 | §2-④ 순서로 찾는다. 답이 나오면 A 로 처리하고 출처(티켓·댓글 번호)를 근거로 적는다 | 근거를 찾음 → A. 못 찾음 → C |
| **C. HAE 질문** | 자료끼리 다름(가이드 ↔ 배포본 ↔ 이전 HAE 답변) / 가이드가 당사 구성 조건을 밝히지 않음 / 배포본 누락·오류 의심 / B 로 찾아도 근거 없음 | S7 질문. 한 패치의 질문은 한 댓글에 모은다. 답을 받을 때까지 판정표에 "HAE 확인 중"과 잠정 처리(보수적 값)를 둔다 | 답변 받음(질문 번호마다). 빠진 번호는 다시 묻는다 |

판단이 애매하면 한 단계 보수적인 쪽(A→B, B→C)으로 간다. D 는 위험을 피하는 기본값이지 결론이 아니다 — 보류 뒤에도 개발 차종 적용 검토가 필요하면 별도로 올린다.

## 2. 공통 사전 점검 (패치 시작 시)

S1 에 들어가기 전에 한다. ①은 프로젝트 프로필에 한 번 만들어 두고 패치 때마다 바뀐 것이 없는지만 확인한다.

HAE 답변의 조건이 되는 값들이다. 이것이 정리돼 있으면 "당사가 X 면 해당 없음"류의 질문을 스스로 판정할 수 있다.

| PFee 사용 여부 (FBL / APP 따로) | PMem_Driver 추가 여부, Pfee.h, PFee_Process Task (255, 280, 256) |

### ② 배포본 완결성

- 안내 댓글·IM 이 언급한 파일 목록과 배포본에 실제 있는 파일을 대조한다. 언급됐는데 없는 파일(예: 3.0.18 의 Ecud_Os·EcuM·Mem General), 있는데 언급 없는 파일을 표로 만든다.
- 티켓의 이후 댓글·첨부에서 보정본, 정정(.ld 값, SCons 입력 누락 보충), 재배포, 삭제를 찾는다. 배포본이 틀렸던 사례가 1년에 5건 이상이었다 — 배포본은 정답이 아니라 참고다.
- Prev 형상(직전 회차)이 보정본과 함께 완성돼 있는지도 같이 본다(예: 3.0.18 = 06-15 zip + 08-31 Ecu.zip·Ecud_Mem_76_Pfls.zip).

### ④ 과거 자료 조사 순서 (B 경로)

1. **같은 티켓의 다른 댓글** — 다른 담당자(다른 차종) 문의와 HAE 답변. `ims_read.js` 로 전체를 읽는다.
2. **같은 과제의 이전 회차 티켓** — 같은 모듈의 직전 FBL/APP 티켓(예: 3.0.19 작업 시 3.0.18·3.0.29 티켓). 정정·보정본·조건부 답변이 거기 있다.
3. **다른 과제의 같은 모듈·버전 티켓** — `ecody-search` IMS JQL (`summary ~ "Delivery_Patch"` + 모듈명). 다른 SWP 계열이라도 모듈 동작 답변은 같다.
4. **ECM 새 IM 페이지** — 옛 링크가 권한 없음이면 제목 `[IM] <모듈> - R44`(또는 `- 2.X`)로 검색. IM 은 2026 하반기에 새 페이지로 일괄 이전됐다(ims-workflow.md §4 대응표).
5. **수평전개(CPINFO) 티켓** — 결함 원인과 코드 변경. usercode 대조 근거.

찾은 근거는 판정표 "근거" 칸에 티켓·댓글 번호로 남긴다. 이 조사를 하고도 없을 때만 C 로 간다(HAE 도 "기술지원 문의 전 FAQ 사전 확인"을 요구).

### ⑤ 작업 수단 — ARXML 직접 편집인가, 툴(mobilgene CLI / C Studio)인가

판정표 행마다 "어떻게 바꿀지"도 미리 정한다. 툴이 없거나 느려도 아래 조건이면 직접 편집으로 충분하고, 그렇지 않으면 툴로 한다. 직접 편집은 `scripts/arxml_block.py`(컨테이너 블록 복사·삭제·이름 변경·값 변경, SD 기록값 동기화, CRLF 보존)를 쓴다.

| 직접 편집으로 충분 (모두 해당) | 툴을 써야 함 (하나라도 해당) |
|---|---|
| 바뀌는 값·블록이 적고 위치가 정해져 있음 (파라미터 값, 컨테이너 몇 개 추가·삭제·이동·이름 변경) | **Harmonize 가 실제로 필요** — DBC 재import, Can/CanIf 재생성, Rte 대량 변경 (수백 줄 + UUID·참조가 같이 바뀜) |
| 새로 만드는 항목은 HAE 배포본에 툴이 만든 원본 블록이 있음 (그대로 이식) | 배포본에 원본 블록이 없는 **새 기능 설정** — 툴이 기본값·필수 하위 항목을 채워야 함 |
| patch_tool 자동 수정 규칙을 당사 설정에 대 보니 위반 0 (S9 Validation 사전 점검) | patch_tool 자동 수정이 **실제로 걸림**(위반 여러 건) — 규칙별 수정 로직을 그대로 쓰는 편이 안전 |
| 다른 파일이 그 이름·경로를 참조하지 않거나, 참조처를 git grep 으로 모두 찾을 수 있음 | 여러 파일에 걸친 **구조 변경**(예: 모듈 제거 5곳) — 참조가 끊기면 Generate 에서야 드러남 |

직접 편집했을 때 툴 대신 지켜야 할 것: (1) ADMIN-DATA `SD GID` 기록값을 VALUE 와 같이 바꿈, (2) XML 파싱 확인, (3) S9 재대조로 사유 없는 차이 0, (4) 빌드의 생성기 Error 0 · Rte Validation 0 errors 로 툴 검증을 대신함, (5) 생성 코드 변화를 하나씩 설명(S10).

사례 — HE1i FBL V3.0.19(#48891): 툴 없이 6파일 약 80줄을 직접 편집. EcuM Dcm_Init·SCons Dcm 입력은 HAE 블록 이식, ListThree 는 블록 삭제, IA-079 는 Harmonize 대신 0x7DF HwObject 값 3개만 수정. 생성기 Error 0, Rte Validation 0 errors, 생성 코드 변화 전부 설명됨. Com 제거(5곳 구조 변경)는 툴 판단 대상이라 보류.

## 3. 산출물

P 단계가 끝나면 다음이 있어야 한다.

- 프로필 "구성 전제" 표 (확인 날짜 갱신)
- 배포본 완결성 표 (언급 ↔ 실제, 보정본 목록)
- 위험 포인트에서 뽑은 판정표 초기 행 (모듈 계열 / 확인할 것 / 예상 경로 / 작업 수단)
- B 조사 대상 목록 (이전 회차·다른 과제 티켓 키)

이후 S6 판정표는 항목마다 `판정 / 경로(A~D) / 근거`를 갖는다. S7 질문은 C 경로 항목만 모아서 하고, S11 Redmine 코멘트의 "적용 제외 사유"는 D·B 경로 근거를 그대로 쓴다.
