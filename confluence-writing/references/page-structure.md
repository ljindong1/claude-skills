# 페이지 구조 규약 — 트리·구조·명명·보일러플레이트

## 1. 전체 트리 구조 (2레벨 기본)

```
[Level 1] 대표 페이지 (목차 페이지)
   ├── [Level 2] 하위 페이지 1  ← 목차 항목 1
   ├── [Level 2] 하위 페이지 2
   └── [Level 2] 하위 페이지 N
```

- 기본 2레벨. 세분화가 필요하면 같은 Level 2에 형제로 배치.
- **사용자 명시 요청 시에만 3레벨(손자) 허용** — Claude 임의 결정 금지. 명시 요청 예: "손자 페이지를 두자", "3레벨까지 가자". 손자의 `parentId`는 해당 Level 2 페이지 ID, 손자 제목은 "2.1 …" 형식 권장, 손자의 부모는 손자 목차 표 포함.
- Part / Section / Group 같은 중간 묶음 페이지 금지 (손자에서도 동일).
- 하위 페이지 5~12개 권장. 13개 이상이면 가이드 분리 또는 항목 통합.
- 모든 하위 페이지의 `parentId`는 동일한 대표 페이지 ID.

## 2. 페이지 종류별 구조

| 종류 | 위치 | 권장 구조 | 다이어그램 |
| --- | --- | --- | --- |
| **대표 페이지** | Level 1 | 개념 → 다이어그램 → 하위 페이지 목차 | **필수** ⭐ |
| **개념 설명** | Level 2 | 리드 → 다이어그램 → 본문 | **권장** ⭐ |
| **Q&A 형식** | Level 2 | 리드 → 다이어그램(가능 시) → Q1~Qn → 추적 흐름 요약 | 권장 |
| **튜토리얼/설치** | Level 2 | 리드 → 사전 확인 → 단계 흐름도 → 트러블슈팅 | 권장 |
| **시스템 구성도** | Level 2 | 다이어그램 → 색상/화살표 의미 → 핵심 통찰 | **주인공** |

### 2.1 대표 페이지 3블록 (순서 고정)

```
[블록 A: 간단한 개념]     가이드가 무엇인지 1~2 문단 + 분야 비유 1회 권장
[블록 B: 시스템 다이어그램] 전체 구조/연결성/흐름 한눈에 + 색상/화살표/통찰 블록
[블록 C: 하위 페이지 목차]  각 항목 설명 표 (제목·요약) + 학습 순서 표(선택) + ⭐ 필독 표시
```

### 2.2 하위 페이지 골격

```
[리드 문단]         이 페이지가 무엇을 다루는지 1~2줄 (일반 단락 — 기울임꼴 *...* 금지)
[다이어그램]        가능하면 (ASCII 또는 SVG 첨부 자리)
[> ⚠️ blockquote]  분야별 사전 경고 (해당 시)
---
[본문 — H3/H4 의미 단위]
```

하위 페이지는 그 자체로 완결된 한 편의 글이어야 한다 — 대표 페이지로 돌아가지 않아도 이해 가능.

## 3. 페이지 간 연결·내비게이션 정책 (링크 최소화)

교차 참조가 촘촘해지면 번호·구조 변경 시 본문 수정 부담이 커진다. 기본 규칙:

| 요소 | 기본 방침 |
| --- | --- |
| "다음 단계 / 이전·다음 / 대표로 돌아가기" 안내 | ❌ 넣지 않음 |
| "이 페이지의 위치" 안내 | ❌ 넣지 않음 ("전체 구조는 대표 페이지 참조" 한 줄도 생략) |
| 형제·부모 페이지 하드 링크 | ❌ 기본 미사용 — **사용자 명시 요청 시에만**, 지정한 방향만 |
| 대표 페이지의 하위 목차 | 제목 텍스트 + 설명만, **링크 없이** (자식 트리 탐색은 사이드바에 위임) |
| 본문 내 형제 주제 언급 | △ "8.3에서 다룬다"처럼 번호·제목 텍스트만, `<a>` 금지 |

> ⚠️ 이 정책에 따라 **"하위 페이지 생성 후 대표 페이지 목차에 URL을 채워 update하는 후속 작업은 하지 않는다.** (구판 스킬 §8.1 8단계는 이 정책과 모순된 잔재였음 — 폐기.) 링크 연결은 사용자가 명시 요청할 때만, 별도 수정 작업(허락+fetch)으로 수행.

## 4. Q&A 형식 페이지 (특수 패턴)

```
[리드] → [> 📌 페이지 가치 한 줄] → [다이어그램] → [Q 흐름 목록]
---
### Q1. [질문]
**답**: [한 줄 결론]
[본문 풀이 2~5 문단] + [표/코드] + [비유/통찰]
---
### Q2. ... (반복)
---
### 📋 종합 정리 (Tier 분리 / 권장 정책 / 의사결정 매트릭스)
### 🎯 추적 흐름 요약   ← Q&A 페이지의 식별 시그니처, 누락 금지
Q1. [질문 압축] → [답 압축]
...
### 💡 이 페이지가 다루지 못한 영역
```

항목 길이: 짧은 Q = 답 1줄 + 1문단 + 표/비유 1개 / 중간 Q = 3~5문단 + 표 + 비유 / 긴 Q(⭐) = 5+문단 + 표 2개 + Tier 분리 + 통찰. Q 항목 5~15개, 초과 시 분할.

## 5. 명명 규약

```
[Level 1 대표] 간결한 명사구 + "가이드/정리/노트/워크플로우" 종결어 권장
  예: "AUTOSAR BSW 통합 가이드", "React 상태 관리 패턴 가이드", "ETL 파이프라인 구축 가이드"

[Level 2 개념 설명]  한국어 명사구/동명사구. "Part 1.", "1장." 접두 금지
[Level 2 Q&A]       "[주제] — N단계 Q&A" (em-dash 시그니처)
[Level 2 구성도]     "[대상] 아키텍처" 또는 "[대상] 구성도"
[Level 2 튜토리얼]   "[대상] [동작]" — 예: "Tessy 설치 및 초기 설정"
```

금지: Part/장 번호 접두, Title Case 영문 제목 (한국어 + 필요 시 괄호 영어 부제).

## 6. 보일러플레이트

> 표가 포함되면 confluence-ops §2 규칙에 따라 **html로 작성 + 셀 data-colwidth 폭 지정** (아래 markdown 골격을 XHTML로 옮겨 씀 — `<colgroup>` 직접 작성 금지, formatting-cheatsheet §2.2). 표 없는 페이지는 markdown 그대로. 본문은 H3부터, H1·H2 금지.

### 6.1 대표 페이지 (Level 1)

````markdown
<!-- title: [가이드 명칭] — 본문 H1 없음 -->

[가이드의 한 문장 정의. 누구를 위한 것인지. — 일반 단락, 기울임꼴 금지]

[2~4 문장 개념 설명 + 분야 비유 1회 권장]

### 📐 전체 구조

<!-- 단순: ASCII 즉시 포함 / 복잡: SVG 첨부 자리 표시 -->
```
[ASCII 다이어그램]
```

<!-- 또는 -->
> 📌 **SVG 첨부 필요**
>
> 이 자리에 SVG 파일 `[파일명].svg`을 드래그 앤 드롭으로 업로드해 주세요. Confluence가 SVG를 그대로 렌더링합니다. 업로드 후 본 안내 박스는 삭제 가능합니다.

#### 다이어그램 보는 법
- **회색** — [의미]
- **파란색** — [의미]

#### 핵심 통찰 ⭐
1. [통찰 1]
2. [통찰 2]

> 📌 **이 가이드의 본질**
>
> [핵심 메시지 한 단락]

> ⚠️ **사전에 인지해야 할 사항**
>
> - [분야별 사전 고려]

---

### 📖 하위 페이지 목차

<!-- 링크 없이 설명만 (§3 연결 정책) -->
| # | 제목 | 한 줄 설명 | 중요도 |
| --- | --- | --- | --- |
| 1 | [제목] | [설명] | ⭐ 필수 |

### 🎯 학습 순서 추천

| 단계 | 권장 시점 | 학습 항목 |
| --- | --- | --- |
| **1단계** | 도입 결정 직후 | [항목 1] → [항목 2] |

> 💡 **꼭 정독해야 하는 항목**
>
> [⭐ 항목 안내]
````

### 6.2 개념 설명 하위 페이지 (Level 2)

````markdown
### 📐 [다이어그램 제목]   <!-- 가능 시 -->
```
[ASCII]
```
---

| --- | --- | --- |
| **[항목]** | [설명] | [분야별 비유] |

````

### 6.3 Q&A 하위 페이지 (Level 2)

§4 구조를 그대로 골격으로 사용. title은 "[주제] — N단계 Q&A".

### 6.4 시스템 구성도 하위 페이지 (Level 2)

````markdown
[이 다이어그램이 무엇을 보여주는지 한 줄 — 일반 단락, 기울임꼴 금지]

### 📐 시스템 구성

> 📌 **SVG 첨부 필요**
>
> 이 자리에 SVG 파일 `[파일명].svg`을 드래그 앤 드롭으로 업로드해 주세요. (안내문 §6.1과 동일)

---
### 다이어그램 보는 법
#### 색상의 의미 / #### 화살표가 말하는 것 / #### 이 그림의 핵심 통찰 ⭐
---
### 🎯 [분야별] 활용 관점
````

### 6.5 링크 문법 (사용자가 링크를 명시 요청한 경우만)

표준 GFM 링크 + 절대 URL. 대상 인스턴스의 URL을 사용한다:

- 사내: `[표시 제목](https://mobaseasec.atlassian.net/wiki/spaces/[스페이스]/pages/[ID])`
- 개인: `[표시 제목](https://ljindong.atlassian.net/wiki/spaces/TECH/pages/[ID])`

tinyui 링크(`/x/A4AAHQ`)도 해당 인스턴스의 절대 URL로 풀어서 사용.

## 7. 커스터마이징 포인트 / Don't

조정 가능: 이모지 빈도(학습용 적극/표준 문서 절제), 표 컬럼 수(3~4), 비유 깊이, Q&A 항목 수(5~15), blockquote 종류 분포.

Don't:
- ❌ 사용자 요청 없이 3레벨 이상
- ❌ Part/중간 묶음 페이지, Part·장 번호 접두
- ❌ 대표 페이지 3블록 중 하나라도 생략
- ❌ 하위 13개 이상
- ❌ 대표 목차에 하드 링크 (명시 요청 시만)
- ❌ Q&A 추적 흐름 요약 누락
