# 아침 브리핑

슬랙 **아침 비서**다. **직전 아침 브리핑 이후부터 지금까지**의 슬랙 메시지를 **감시 소스 전수 소인**으로 빠짐없이 모은 뒤, 두 갈래로 정리해 **대상의 슬랙 DM으로 보낸다**.

- **§A 내 업무** — 대상 개인에게 액션·일정·참고가 되는 것 (기존 3섹션)
- **§B 채널 동향** — 채널별로 그 창의 흐름을 요약 (개인 관련 여부와 무관)

이 스킬은 매일 아침 도는 **예약 루틴**이 호출하는 자동 발송용이다. 사용자가 채팅에서 직접 부르는 즉석 요약은 `slack-brief`가 담당한다. **자동·DM 발송·직전 브리핑 이후 기준이면 이 스킬이다.**

## 이 스킬의 제1 원칙

> **수집(Phase A)과 판단(Phase B)을 분리한다. 수집 단계에서는 관련성을 일절 판단하지 않는다.**

과거의 모든 누락 사고는 같은 모양이었다 — *판단 기준에 안 걸리는 것은 읽히지도 않았다.* 그래서 이 스킬은 먼저 **정의된 소스를 전수로 읽어 담고**, 그 다음에 **명시적 제외 사유가 있는 것만 걷어낸다.** "관련 없어 보임"은 제외 사유가 아니다.

**실측된 누락 사례 (2026-07)**: `@channel` 전사 공지, 프로젝트 채널의 일정 변경("PSU proto 내년 1월 연기"), 요구사항 확인 요청(REQ-SRS-NVM-012), 스탠드업 11건 전부 — 3일 연속 누락. 원인은 전부 "채널을 읽지 않았다"였다. 그리고 누락 채널 2개는 **스킬의 채널 목록에 아예 없었다.**

## 전체 흐름 (9단계)

```
P0  컨텍스트 확정   TODAY/DOW/NOW · 대상 · 실행모드          [scripts/context.py]
P1  창 확정         직전 브리핑 ts (ts만 취함)
P2  소인 계획       sources.json 로드 → ledger 생성 (전 소스 pending)
──────────────── Phase A : 무판단 기계 수집 ────────────────
P3  전수 소인       소스별 slack_read_channel(oldest=창시작)
P4  발견 스윕       미등록 소스 검출 → 즉시 소인 + 갱신 경고
P5  ★게이트#1       ledger 에 pending 잔존 시 진행 금지
──────────────── Phase B : 판단 ────────────────
P6  선별·분류       기본 채택. 제외는 사유코드 필수
P7  작성            §A 내 업무 + §B 채널 동향
P8  ★게이트#2       날짜 assert + 커버리지 assert + 회계 assert
P9  발송 + 감사 푸터
```

**참조 문서** — 해당 단계에 들어갈 때 반드시 읽는다.

| 단계 | 문서 |
| --- | --- |
| P2~P5 | `references/collection.md` — 수집 절차·도구 인자·실측 제약 |
| P6 | `references/exclusion.md` — 제외 사유 코드 정의 |
| P7 | `references/format.md` — 출력 형식·서식 규칙 (정본) |

## P0. 컨텍스트 확정

### 대상 확정

- 사람 지정이 **없으면** → 대상 = **이진동 `U0B8UFCATRU`** (기본, 본인 DM)
- `@홍길동` / `홍길동 브리핑` / `홍길동한테` 처럼 지정되면 → 그 사람이 대상. `slack_search_users`로 user ID·표시이름을 확정한다.
  - 후보가 애매하면 **수동 호출에서만** 되묻는다. 무인 루틴에서는 되묻지 말고 기본 대상으로 폴백한다.

### 날짜·시각 확정 (기계값만 신뢰)

```bash
python3 scripts/context.py now
```

`TODAY`(YYYY-MM-DD) · `TODAY_DOW`(월~일) · `NOW_KST` · `NOW_EPOCH` 를 JSON으로 반환한다. **이 값이 오늘의 유일한 진실이다.** 직전 브리핑 헤더의 날짜·요일·문구는 어떤 경우에도 재사용하지 않는다(복사하면 하루씩 밀려 굳는다 — 실측된 실패 모드).

스크립트를 쓸 수 없는 환경이면 `TZ='Asia/Seoul' date '+%Y-%m-%d %u %H:%M'` 로 대체하고, 요일 매핑은 `1=월 2=화 3=수 4=목 5=금 6=토 7=일`.

## P1. 창(window) 확정

수집 시작점은 **이 대상에게 보낸 직전 아침 브리핑 시각**이다.

1. 대상 DM에서 직전 브리핑을 찾는다.
   - 기본 대상: `slack_read_channel(channel_id="U0B8UFCATRU", limit=5)` 로 최신 메시지를 읽어 `🌅 ... 아침 브리핑` 헤더로 시작하는 가장 최근 것을 고른다.
   - 대상 지정 시: 그 대상 DM 범위로 한정해 같은 방식으로 찾는다(`🌅 홍길동님 아침 브리핑`).
2. **그 메시지의 `ts`(기계값)만** 취한다. 헤더 문구·날짜·요일은 취하지 않는다.
3. 못 찾으면(최초 실행 등) → **어제 0시**로 폴백.
4. 경계 중복을 막기 위해 그 브리핑 메시지 자체는 범위에서 제외한다.

## P2. 소인 계획 생성

```bash
python3 scripts/context.py init --window-start <창시작 unix초>
```

`sources.json`을 읽어 작업 디렉터리에 `ledger.json`을 만든다. 모든 소스가 `pending` 상태로 시작하며, P3에서 하나씩 `swept`로 바뀐다. **이 원장이 P5·P8 게이트의 검사 대상이다.**

## P3~P5. Phase A — 전수 소인

**`references/collection.md`를 읽고 그대로 수행한다.** 요지만 옮기면:

- 채널은 **`slack_read_channel(channel_id, oldest=창시작)`로 전수 열람**한다. 검색으로 대체하지 않는다 — 검색은 modifier만으로 채널을 훑을 수 없고(실측), 비공개 채널은 공개 검색에 아예 안 잡힌다.
- DM도 같은 방식 + `slack_search_public_and_private(query="to:me", channel_types="im,mpim", after=창시작)`.
- `Reply count`가 있는 메시지는 `slack_read_thread`로 답글까지 가져온다.
- **발견 스윕**으로 `sources.json` 밖 채널을 검출한다. 잡히면 즉시 소인하고 브리핑 말미에 등록 제안을 붙인다.
- 소스를 하나 끝낼 때마다 `python3 scripts/context.py mark --source <id> --count <건수>`.

**소스 수명주기** — 채널은 생기고, 아카이브되고, 사라진다.

| 상황 | 처리 |
| --- | --- |
| 신규 채널 | 발견 스윕이 잡는다 → 즉시 소인 → 푸터에 등록 제안 (등록 전까지 매일 재안내) |
| 아카이브됨 | `read_channel`이 성공하며 0건 반환 — 게이트를 막지 않는다. 30일 연속 0건이면 정리 제안 |
| 삭제·이탈 (`channel_not_found`) | **재시도 금지.** `mark --status unavailable --reason not_found` 로 명시 처리하고 진행. 푸터에 반드시 표시 |

> 오류 난 소스를 `pending`으로 남기면 게이트#1이 영원히 막혀 **무인 루틴에서 브리핑이 아예 안 나간다.** 그건 누락보다 나쁜 조용한 전면 실패다. 접근 불가는 통과시키되 **반드시 보이게** 만든다.

게이트 #1:

```bash
python3 scripts/context.py gate-coverage   # pending 남아 있으면 exit 1
```

실패하면 **P3으로 돌아가 마치기 전까지 다음 단계로 가지 않는다.**

## P6. Phase B — 선별·분류

**`references/exclusion.md`를 읽고 그대로 적용한다.** 원칙:

> **감시 소스의 사람 메시지는 기본 채택.** 제외하려면 `BOT` `REACTION` `DUP` `SOCIAL` `SELF` `NOISE-CONFIRMED` 중 하나에 해당해야 한다. **"관련 없어 보임"은 제외 사유가 아니다.**

채택한 것을 두 갈래로 배분한다.

- **§A 내 업무** — 대상이 멘션됨 / 대상에게 온 DM / 대상이 참여한 스레드 / 대상의 이름·담당 업무가 언급됨 / 대상이 해야 할 액션·참석·제출이 있음 / `@channel`·`@here` 전사 공지 중 대상에게 행동이 필요한 것
- **§B 채널 동향** — 그 외 전부. 채널별로 묶는다.
- §A에 실은 건은 §B에서 `→ 내 업무 §1 참조` 한 줄로만 남긴다(중복 서술 금지).

제외한 건은 반드시 사유코드와 함께 기록해 둔다. 다음에 "왜 빠졌지?"를 즉답할 수 있어야 한다.

## P7. 작성

**`references/format.md`가 출력 형식의 정본이다.** 헤더·이모지·순서·머리표·링크라벨·표 규칙을 매번 글자 그대로 지킨다.

## P8. 게이트 #2 — 발송 전 하드 게이트

```bash
python3 scripts/context.py gate-final \
  --header "<완성된 헤더 첫 줄>" \
  --collected <수집 총건> --adopted <채택> --dropped <제외>
```

검사 항목:

1. `헤더의 YYYY-MM-DD == TODAY` (하루 밀림 차단)
2. 헤더에 요일 표기가 있으면 `== TODAY_DOW`
3. `TODAY`로부터 재계산한 요일 `== TODAY_DOW`
4. ledger 에 `pending` 0건 (커버리지)
5. `collected == adopted + dropped` (회계 — 누수 0)

추가로 모델이 직접 확인할 것:

6. §B 일정표·본문의 모든 `M/D(요일)`가 그 날짜에서 재계산한 요일과 일치하는가

**하나라도 실패하면 전송하지 않는다.** 헤더는 부분 수정하지 말고 `references/format.md` 골격으로 **처음부터 새로 만든다**(옛 템플릿이 딸려 온다). 무인 루틴에서도 되묻지 말고 재산출→재검증 후 발송한다.

## P9. 발송

`slack_send_message`로 **대상 DM 한 곳에만** 보낸다. `channel_id`에는 P0에서 확정한 대상의 user ID(기본 `U0B8UFCATRU`).

- 슬랙에는 이 브리핑 **외 어떤 글도 쓰지 않는다.** 반응(이모지)도 달지 않는다.
- **일정 등록은 하지 않는다.** 발견한 일정은 브리핑에 정리만 하고, 캘린더 등록은 `slack-to-calendar`가 따로 처리한다.
- 지정 대상이 있으면 그 사람에게 이진동 명의로 실제 DM이 나가므로 **수신처를 반드시 재확인**한다.

## 루틴(무인) 실행 모드

- **되묻지 않는다.** 대상이 모호해도 기본 대상(이진동)으로 폴백해 진행한다.
- **빈 브리핑도 발송한다.** 채택 항목이 하나도 없어도 헤더는 실제 날짜로 찍고 골격을 유지해 보낸다.
- 게이트 실패 시에도 멈추지 말고 재산출→재검증 후 발송한다(빈 브리핑이라도 날짜와 커버리지만은 정확히).
- 발송 주기(매일/평일 등)는 스킬이 아니라 **루틴 설정**에서 정한다. 이 스킬은 "직전 브리핑 이후만 수집"이라 어떤 주기에도 그대로 동작한다.

## 접근 권한 한계 (비서 대행 시)

슬랙 커넥터는 이진동 계정이다. 대상이 다른 사람이어도 **이진동이 접근할 수 있는 범위**만 보인다. 대상이 남과 주고받은 비공개 DM은 안 보인다. 이때는 `to:me`·DM 로스터를 쓰지 말고 **채널에서 그 사람이 멘션·언급된 것 위주**로 모으고, 안 보이는 영역이 있음을 감안한다. 남에게 보내는 DM은 이진동이 보낸 메시지로 표시된다.

## 경계 / 주의

- **누락 > 과수집.** 애매하면 넣는다. 이 원칙과 수집 규칙이 충돌하면 수집 규칙이 틀린 것이다.
- **소스 집합은 데이터다.** 채널을 본문에 예시로 적지 말고 `sources.json`에 id로 박제한다. 새 채널은 발견 스윕이 잡아낸다.
- **게이트는 기억이 아니라 산출물을 검사한다.** "수집했다"는 자기신고를 assert로 쓰지 않는다.
- **직전 브리핑은 시작 `ts` 조회용으로만 읽는다.** 헤더·날짜·요일·템플릿을 복사하지 않는다.
