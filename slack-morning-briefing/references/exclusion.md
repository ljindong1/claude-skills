# Phase B — 선별 규칙 (P6)

## 기본값은 채택이다

> **감시 소스에서 수집된 사람 메시지는 전부 채택한다.**
> 빼려면 아래 6개 사유코드 중 하나에 해당해야 한다.
> **"관련 없어 보임", "중요하지 않아 보임"은 사유가 아니다.**

이 반전이 이 스킬의 핵심이다. 과거 규칙은 화이트리스트(관련 있는 것만 넣기)였고, 그래서 판단 기준에 없던 `@channel` 전사 공지가 규칙대로 판정해도 정당하게 탈락했다. 스킬의 원칙(`누락 > 과수집`)과 문언이 모순이었던 셈이다.

## 제외 사유 코드

| 코드 | 정의 | 예 |
| --- | --- | --- |
| `BOT` | 봇·앱의 자동 알림 | agent-m 근태 알림, Google Calendar 일정 알림, CI 알림 |
| `REACTION` | 이모지 반응만 있고 텍스트·첨부가 없음 | 👍 만 달린 것 |
| `DUP` | 직전 브리핑에 이미 실려 나간 동일 건 | 창 경계에 걸친 중복 |
| `SOCIAL` | 순수 인사·잡담·감사 표현만, 업무 정보 0 | "감사합니다", "좋은 하루 되세요", "넵" |
| `SELF` | 대상 본인의 발화 | 단, **본인 스탠드업의 "오늘 할 일"·"이슈/막힌 점"은 §A 후보로 예외 채택** |
| `NOISE-CONFIRMED` | 사용자가 명시적으로 "이건 빼라"고 지정한 패턴 | 사용자 지시가 있을 때만 |

### 판단이 애매할 때

**채택한다.** 애매한 것을 §B 채널 동향의 한 줄로 넣는 비용은 거의 0이고, 빼는 비용은 이번 같은 사고다.

특히 아래는 **반드시 채택**한다 — 과거 누락이 실제로 발생한 유형이다.

- `@channel` / `@here` 전사 공지 — 개인 멘션이 없어도, 본문에 대상 이름이 없어도 채택
- 파일·문서 공유 (본문이 한 줄뿐이어도)
- 일정 신설·변경·취소·연기
- 질문·요청·검토 의뢰 (수신자가 대상이 아니어도 §B에 남긴다)
- 결정 사항·사양 변경
- 이슈·블로커·장애

## 배분 — §A 내 업무 vs §B 채널 동향

채택한 건을 두 갈래로 나눈다.

### §A 내 업무로 보내는 조건 (하나라도 해당)

- 대상이 `@멘션`됨
- 대상에게 온 DM
- 대상이 참여 중인 스레드의 새 답글
- 대상의 이름·담당 업무가 언급됨
- 대상이 해야 할 액션이 있음 (회신·검토·제출·참석·준비)
- 대상이 참석·관여하는 일정
- 전사 공지 중 **대상에게 행동이 필요한 것** (예: 자료 사전 검토, 참석 대상 회의)

### §B 채널 동향으로 보내는 것

그 외 채택분 **전부**. 채널별로 묶는다. 대상과 무관해 보여도 넣는다 — §B의 목적이 "내 주변에서 무슨 일이 있었나"를 보는 것이기 때문이다.

### 중복 처리

§A에 실은 건은 §B에서 **한 줄 참조만** 남긴다.

```
• [최연훈 07/30 10:45] @channel 연구개발실 소개 자료 공유 → 내 업무 §1 참조
```

같은 내용을 두 번 서술하지 않는다.

## 회계 (P8 게이트가 검사한다)

```
수집(collected) = 채택(adopted) + 제외(dropped)
```

이 등식이 안 맞으면 어딘가에서 조용히 사라진 것이다 — 게이트에서 걸린다.

제외한 건은 **사유코드와 함께 기록**해 둔다. 나중에 "왜 빠졌지?"라는 질문에 즉답할 수 있어야 한다. (이번 원인 규명에 도구 호출 10여 회가 든 이유가 정확히 이 기록의 부재였다.)

권장 기록 형식 — `dropped.jsonl`:

```json
{"ts":"1785459236.123","source":"C0BCY4F9E86","author":"agent-m","reason":"BOT","gist":"근태 알림"}
```
