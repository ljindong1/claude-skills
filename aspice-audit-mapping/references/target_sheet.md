# Target 시트 구조와 파싱 규칙

사내 품질점검 체크리스트의 `Target_*` 시트는 **점검 대상 산출물 목록**이다.
체크리스트 3계층(Target / Process Checklist / WP Checklist) 중 범위 정의 계층에
해당하며, 본 스킬은 이 시트만 읽는다.

## 표준 구조 (JX HEV_CCP 체크리스트 V1.0 기준 실측)

- 시트명: `Target_<단계명>` (예: `Target_P1 소프트웨어 설계`) — 파서는
  `Target`으로 시작하는 첫 시트를 자동 선택하고, `--sheet`로 명시 지정도 가능
- 1행: 제목("점검 대상")
- 3행: 헤더 — `No. | 프로세스/절차/지침/가이드 | 출력 작업 산출물 | 파일 명 또는
  관련 URL | 비고 | Note | (일자)`
  - 파서는 "No."와 "출력 작업 산출물"이 함께 있는 행을 헤더로 탐지한다(행 번호 고정 아님)
- 4행~: 데이터 행. `출력 작업 산출물`이 비면 스킵
- 말미: `<작성 지침>` 행부터는 작성 안내 — 이 행을 만나면 파싱 종료

## 열 해석 규칙

| 열 | 해석 |
|---|---|
| No. | 시트 고유 번호 — 안정 식별자 `T-0nn`의 근거. 연속이 아님(중간 결번 존재) |
| 프로세스/절차/지침/가이드 | 점검 기준이 되는 사내 절차 그룹 (12종 내외) |
| 출력 작업 산출물 | 점검 대상 산출물명 (사내 용어) |
| 파일 명 또는 관련 URL | 실제 파일명 — **셀 안 개행으로 다중 파일**, `http` 시작이면 시스템 URL. 선행 `-`(불릿) 제거 후 사용 |
| 비고 | `[점검 대상]` / `[점검 미대상]` 판별 + 부가 설명. "미대상"이 포함되면 제외 항목(사유 보존) |
| Note | 점검자 메모 — 매핑에는 미사용, 보존만 한다 |

## 변형 허용 범위

- 헤더 행 위치, 데이터 시작 행이 달라도 헤더 탐지로 흡수한다.
- 열 순서가 다르면 헤더 텍스트로 열을 찾는다(부분 일치: "산출물", "파일", "비고").
- 아래 경우는 **파싱 중단 + 사용자 보고** 대상이다 (추측 진행 금지):
  - `Target` 시트가 없음
  - 헤더 탐지 실패 (No./출력 작업 산출물 열을 못 찾음)
  - 데이터 행 0건

## 주의

- 파일명 셀에는 확장자 누락(예: `...명세서_V1.0`), 접미 설명, 후행 `/` 등이
  섞인다 — 매칭 단계의 정규화가 흡수하므로 파서는 원문 그대로 보존한다.
- `[점검 대상] 형상항목관리대장 참고` 처럼 비고에 대상 표시와 참조 설명이 함께
  있는 경우: 대상 여부만 판별하고 나머지는 `remark`로 보존한다.

## v0.3 추가 — 시트 식별·행 파싱 규칙

- **시트 식별**: 시트명이 `Target`으로 시작(대소문자·전각 무시, 앞뒤 공백 허용)하는
  시트가 후보. 1개면 채택, 2개 이상이면 `MULTIPLE_TARGET_SHEETS`(PAUSE — 사용자 선택),
  0개면 `TARGET_SHEET_NOT_FOUND`(PAUSE — 모드 B 제안).
- **절차그룹 열 병합 셀**: 빈 셀은 직전 값으로 forward-fill 한다.
- **행 단위 파싱 실패**: 산출물명은 있는데 구조 이상으로 해석 불가한 행은
  `UNPARSEABLE_ROWS`(WARN)로 행 번호·원인을 기록하고 items에서 제외한다 —
  커버리지 검사 분모에서도 제외, 대시보드 경고로 사람이 수기 확인.

## v0.4 추가 — No. 유일성 (DUPLICATE_ITEM_NO)

- No. 열에 **중복**이 있으면 안정 식별자 T-nnn을 만들 수 없으므로
  `DUPLICATE_ITEM_NO`(**FATAL**)로 중단하고 중복 행 목록을 제시한다.
  id는 계약의 근간이라 **자동 재부여 금지** — 시트 정비는 사람이 한다
  (계약 규칙 2). 결번은 허용된다(연속일 필요 없음).
