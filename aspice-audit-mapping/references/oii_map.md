# 사내 산출물 ↔ PAM 4.0 프로세스·OII 대응 (근거 해설)

기계 적용본은 `assets/oii_map.json`이다. 이 문서는 그 근거와 원칙을 설명한다.

## 원칙 (프로젝트 판정 철학 준수)

1. **PAM은 WHAT 수준이다.** 사내 산출물과 OII(Output Information Item)의 1:1
   대응을 강요하지 않는다. 하나의 사내 문서가 여러 OII 특성을 담을 수 있고
   (예: 프로젝트 계획서가 일정·자원·의사소통 계획을 포함), 여러 문서가 하나의
   OII를 이룰 수도 있다. 매핑은 "이 산출물이 이 OII의 증거 후보"라는 뜻이다.
2. **확신 없는 대응은 단정하지 않는다.** OII 번호는 PAM 4.0 Annex(정보 항목
   특성) 원문 대조가 끝나기 전까지 `confidence: "확인 필요"`로 둔다.
   프로세스 수준 대응(아래 표)은 프로세스 정의로부터 명확하므로 그대로 쓴다.
3. 대체 증거 인정 시 근거(어느 문서의 어느 절이 해당 특성을 담는지)를 남긴다.

## 절차 그룹 → PAM 4.0 프로세스 (확정 수준)

| 사내 절차 그룹 | 프로세스 | 비고 |
|---|---|---|
| 프로젝트 관리 | MAN.3 | |
| 형상관리 절차 | SUP.8 | |

| 소프트웨어 단위 통합 테스트 절차 | SWE.4~5 | 단위 검증=SWE.4, 통합=SWE.5 |
| 시스템 요구 사항 분석 절차 | SYS.1~2 | 이해관계자 요구=SYS.1, 시스템 요구=SYS.2 |

## 산출물 세분 대응의 근거 (SWE 영역 예)

- 소프트웨어 요구사항 분석서·요구사양서 → **SWE.1** (요구사항 도출·분석)
- 아키텍처 선정 평가서·아키텍쳐 설계서 → **SWE.2** (아키텍처 설계·평가)
- 상세설계서·소스코드 → **SWE.3** (상세설계 및 유닛 구현)
- 정적 검증리포트(QAC 코딩룰·메트릭)·Run-time-error 검증·코드 동료검토 →
  **SWE.4** (유닛 검증 — PAM 4.0에서 정적 검증 포함. 해석 여지 있음 —
  SWE.3 품질보증 관점과 겹침, 원문 확인 필요)
- 단위 테스트 계획·케이스·결과 → **SWE.4**
- 통합 테스트 계획·케이스·결과 → **SWE.5**
- 검토 결과서류(Review Report) → 해당 대상 프로세스 + **SUP.1** 연관
  (동료검토는 대상 산출물 프로세스의 검증 practice 증거)

## OII 번호 취급

`assets/oii_map.json`의 `oii_candidates`는 전부 `확인 필요` 상태로 시작한다.
게이트 5(개선 반복)에서 PAM 4.0 Annex 원문과 대조해 확정하면 confidence를
갱신한다. **원문 대조 전에 OII 번호를 근거로 판정 코멘트를 쓰지 않는다.**

## v0.3 추가 — 절차그룹명 별칭 표 (시트 문자열용, §5.1)

정규화(NFC·공백 정리·개행 제거) 후 정확 일치 → 별칭 일치 → 미일치 시
process=null + UNKNOWN_PROCEDURE_GROUP(WARN). 유사 그룹 추측 배정 금지.
별칭은 실측 양식에서 발견되는 대로 assets/oii_map.json `group_aliases`에 누적한다.

| 별칭 예 | 표준 그룹 |
|---|---|
| SW설계 절차, 소프트웨어 설계 절차 | 소프트웨어설계 업무 절차 |
| 형상 관리 절차 | 형상관리 절차 |
| 품질보증 절차 | 프로젝트 품질보증 절차 |

## v0.3 추가 — 파일명·경로 키워드 사전 (모드 B 추론 + 모드 A UNCLAIMED 추정 공용)

정본은 assets/oii_map.json `keyword_dict`. 하나의 사전만 유지한다.
각 엔트리: {keywords: [...], procedure_group, work_product(표준명), pam}.
파일명+상위 폴더 경로를 NFC 정규화해 대조하며, 단일 그룹 명확 매칭이면
INFERRED_HIGH, 복수 후보·부분 매칭이면 INFERRED_LOW, 미매칭이면 UNCLASSIFIED.
잣대 문서 패턴(절차서·표준 템플릿 — RULER_DOCS_NOT_FOUND 판별용)도 이 파일의
`ruler_patterns`에 둔다.
