# 정리 페이지 누락 원장

검증 모드(SKILL.md S5)에서 찾은 것을 **유형으로** 쌓는다. 한 번 나온 유형은 다음 회차에
그 자리를 먼저 본다. 목적은 `ecody-ims-patch-monitor` 를 고치는 것이다.

두 가지를 구분한다. 섞으면 고칠 수 없는 것을 계속 고치려 든다.

| | 뜻 |
| --- | --- |
| **고칠 누락** | eCoDY 에 있는데 페이지가 안 담았다 → 모니터 스킬을 고치면 된다 |
| **구조적 한계** | 페이지가 원리상 알 수 없다 → 이 스킬이 다른 입력으로 메운다 |

## 끄는 기준

연속 3회차 동안 **새 "고칠 누락" 유형**이 나오지 않으면 검증 모드를 기본에서 뺀다.
구조적 한계는 셈에 넣지 않는다 — 그것은 메워질 성질이 아니다.

## 1. MCP1001-198 (2026-11-06)

### 구조적 한계

| 유형 | 내용 | 이 스킬이 메우는 법 |
| --- | --- | --- |
| **첨부 내용** | 페이지는 IMS 첨부의 **목록과 성격**은 알지만 **내용**을 모른다. 모니터는 첨부를 내려받지 않는다(사람이 받는다는 방침). 이번에 Generate 로그 44개 안에서 `Csm CsmInOutRedirection 필수 컨테이너 누락`(log_FW.log:2410)과 `CanIf CanIfCfgHeader` 에러, `Rte Validation 0 errors / 166→376 warnings` 가 나왔는데 페이지에는 없다 | 첨부 폴더 재귀 수확(S2). **일감 §4 빌드·Generate 결과는 첨부에서만 나온다** |
| **첨부가 "로그"가 아니라 자료일 때** | ⭐ 페이지 §7 은 `Automation_...xls` 를 "EcuM·BswM Harmonize 에러 상세 로그"로 적었다. 실제로는 **Harmonize 대조표**(BswM 1,882행, `Added 16 / Deleted 407 / Different 2`)였고, 그 안에 ⑥의 "HAE 가 기대만 하고 확인하지 않은 항목"과 **빌드 실패(`Com.h`)의 구조**가 들어 있었다. 페이지는 첨부를 열지 않으니 성격을 **제목으로 추측**할 수밖에 없다 | 첨부를 직접 읽는다. 구형 `.xls` 는 엑셀 COM 으로 변환해서 읽는다(`harvest_attach.py`). **"읽을 수단이 없다"고 넘기지 마라** — 넘긴 파일이 일감을 바꿀 내용을 담고 있던 전례가 이것이다 |
| **사내 자료** | 페이지는 **eCoDY 자료만**으로 구성한다(모니터 방침 2026-11-05). Redmine 일감·Gitea 저장소·브랜치는 영원히 안 들어온다 | ASEC 선례 조회(S4) + 제어기 프로필 |

### 확인할 수 없었던 것 — 자료 자체가 없다

| 유형 | 내용 | 일감에 어떻게 적나 |
| --- | --- | --- |
| **Validation 예측의 사실 확인** | 페이지 §3.3 은 `ERR053310`·`ERR053311` 이 걸릴 가능성이 높다고 적었다(FBL 표준이 `DcmDemIntegrated=False` 라서). 그런데 Generate 로그 44개에 `ERR0533xx` 가 **한 건도 없다.** 동시에 로그가 가리키는 Validation 산출 경로(`Build/ruleID.csv`)가 **첨부 폴더에 없다** | **"안 걸렸다"가 아니라 "확인할 자료가 없다"** 로 적는다. §2.6 확인 필요 + 질문/확인 항목 |

예측을 결과로 적어 버리는 것이 이 칸의 함정이다. 페이지가 "가능성이 높다"고 쓴 것은 근거 있는
추정이지만 추정이다. **로그로 확인되기 전까지는 사실이 아니다.**

### 고칠 누락

이번 회차에서는 **없다.** 페이지가 eCoDY 에서 가져올 수 있는 것은 다 가져왔다.
§2.5·§5 에 못 본 것(IMS 403 `MCP0858-296`, ECM 404 `364422955`, 하위작업 12건 본문 없음)을
스스로 적어 둔 것도 정확했다.
