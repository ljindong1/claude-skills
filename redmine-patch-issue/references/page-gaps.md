# 정리 페이지 누락 원장

검증 모드(SKILL.md S5)에서 찾은 것을 **유형으로** 쌓는다. 한 번 나온 유형은 다음 회차에
그 자리를 먼저 본다. 목적은 `ecody-ims-patch-monitor` 를 고치는 것이다.

두 가지를 구분한다. 섞으면 고칠 수 없는 것을 계속 고치려 든다.

| | 뜻 |
| --- | --- |
| **고칠 누락** | eCoDY 에 있는데 페이지가 안 담았다 → 모니터 스킬을 고치면 된다 |
| **구조적 한계** | 페이지가 원리상 알 수 없다 → 이 스킬이 다른 입력으로 메운다 |

## 끄는 기준

연속 3회차 동안 **새 "고칠 누락" 유형**이 나오지 않으면 검증 모드를 기본에서 뺀다.
구조적 한계는 셈에 넣지 않는다 — 그것은 메워질 성질이 아니다.

## 1. MCP1001-198 (2026-11-06)

### 구조적 한계

| 유형 | 내용 | 이 스킬이 메우는 법 |
| --- | --- | --- |
| **첨부 내용** | 페이지는 IMS 첨부의 **목록과 성격**은 알지만 **내용**을 모른다. 모니터는 첨부를 내려받지 않는다(사람이 받는다는 방침). 이번에 Generate 로그 44개 안에서 `Csm CsmInOutRedirection 필수 컨테이너 누락`(log_FW.log:2410)과 `CanIf CanIfCfgHeader` 에러, `Rte Validation 0 errors / 166→376 warnings` 가 나왔는데 페이지에는 없다 | 첨부 폴더 재귀 수확(S2). **일감 §4 빌드·Generate 결과는 첨부에서만 나온다** |
| **첨부가 "로그"가 아니라 자료일 때** | ⭐ 페이지 §7 은 `Automation_...xls` 를 "EcuM·BswM Harmonize 에러 상세 로그"로 적었다. 실제로는 **Harmonize 대조표**(BswM 1,882행, `Added 16 / Deleted 407 / Different 2`)였고, 그 안에 ⑥의 "HAE 가 기대만 하고 확인하지 않은 항목"과 **빌드 실패(`Com.h`)의 구조**가 들어 있었다. 페이지는 첨부를 열지 않으니 성격을 **제목으로 추측**할 수밖에 없다 | 첨부를 직접 읽는다. 구형 `.xls` 는 엑셀 COM 으로 변환해서 읽는다(`harvest_attach.py`). **"읽을 수단이 없다"고 넘기지 마라** — 넘긴 파일이 일감을 바꿀 내용을 담고 있던 전례가 이것이다 |
| **사내 자료** | 페이지는 **eCoDY 자료만**으로 구성한다(모니터 방침 2026-11-05). Redmine 일감·Gitea 저장소·브랜치는 영원히 안 들어온다 | ASEC 선례 조회(S4) + 제어기 프로필 |

### 확인할 수 없었던 것 — 자료 자체가 없다

| 유형 | 내용 | 일감에 어떻게 적나 |
| --- | --- | --- |
| **Validation 예측의 사실 확인** | 페이지 §3.3 은 `ERR053310`·`ERR053311` 이 걸릴 가능성이 높다고 적었다(FBL 표준이 `DcmDemIntegrated=False` 라서). 그런데 Generate 로그 44개에 `ERR0533xx` 가 **한 건도 없다.** 동시에 로그가 가리키는 Validation 산출 경로(`Build/ruleID.csv`)가 **첨부 폴더에 없다** | **"안 걸렸다"가 아니라 "확인할 자료가 없다"** 로 적는다. §2.6 확인 필요 + 질문/확인 항목 |

예측을 결과로 적어 버리는 것이 이 칸의 함정이다. 페이지가 "가능성이 높다"고 쓴 것은 근거 있는
추정이지만 추정이다. **로그로 확인되기 전까지는 사실이 아니다.**

### 고칠 누락

이번 회차에서는 **없다.** 페이지가 eCoDY 에서 가져올 수 있는 것은 다 가져왔다.
§2.5·§5 에 못 본 것(IMS 403 `MCP0858-296`, ECM 404 `364422955`, 하위작업 12건 본문 없음)을
스스로 적어 둔 것도 정확했다.

## 2. MCP1001-199 (2026-11-06)

FBL 회차와 같은 유형이 또 나왔고(첨부 내용), **새 유형 하나**가 드러났다.

### 구조적 한계 — 새 유형

| 유형 | 내용 | 이 스킬이 메우는 법 |
| --- | --- | --- |
| ~~**설정 변경의 1차 출처가 배포본 스크립트다**~~ | **2026-11-06 정정 — 구조적 한계가 아니라 고칠 누락이었다.** 아래 "고칠 누락" 으로 옮겼다 | — |
| **Harmonize 가 한 동작이 아니다** | 배포본 `patch_tool/module_patch/_harmonize/` 에 `[2/8]`·`[5/8]` 단계 표기를 가진 pre/post 처리 스크립트가 들어 있다(`rte_pre/post_harmonize.py`, `bswm_pre/post_harmonize.py`, `gen_harmonize.py`). 페이지는 "harmonize 필요: Rte, EcuM" 한 줄만 적는다. **그리고 manifest 의 `scripts` 는 그중 `clear_harmonize_json.py` 하나만 부른다** — 자동으로 돌지 않는다 | `_harmonize/` 폴더와 `manifest["scripts"]` 를 **대조**한다. 어긋나면 실행 방법을 HAE 확인 항목으로 올린다 (#49951 (사)) |
| **스크립트 머리말이 ECM 문서를 더 가리킨다** | `patch_Dcm_common.py` 가 참조로 ECM `334008428`(`[Mode][R44][SAG]` Ecud_Dcm 변경 시 Bswmd_BswM 수동 설정)을 걸고 있다. **페이지에는 없다.** 모니터는 IMS 티켓과 거기 링크된 ECM 만 따라가므로 첨부 **안쪽**의 참조 URL 은 원리상 못 본다 | 스크립트 머리말의 `Reference:` URL 을 수확해 §6 "받지 못한 자료"나 확인 항목으로 올린다 |

### 맞은 것 — 페이지가 이미 경고하고 있었다

| 내용 |
| --- |
| `EcuMDriverInitItemIndex` 를 페이지는 `55`, 배포본은 `33`, IM 예시는 `42` 로 셋이 달랐다. 페이지가 **"중복 없는 순차 값이면 된다"** 고 적어 둔 것이 맞았다 — 패치 스크립트의 `reindex_init_list()` 가 우선순위 표로 자동 재계산한다. **페이지를 의심하기 전에 페이지가 뭐라고 적었는지 다시 읽어라** |
| 페이지가 "확인해 두면 좋다"고 남긴 `ECUM_CAUSE_DCM`(Id 3)은 배포본에 **있었다**. 페이지는 당사 형상을 모르니 확인 항목으로 넘긴 것이고, 그 판단이 옳았다 |

### 또 막힌 것

| 자료 | 상태 |
| --- | --- |
| ECM `364422955` (`MCAL 보증 범위 안내`) | FBL 회차에서 404 였고 **2026-11-06 재시도에도 404**(`authorized: false`). 권한 요청이 필요하다. 번호와 제목은 IMS 티켓 본문의 링크에서 왔다 |

### 고칠 누락 — ⭐ 참조 가이드의 **안쪽 절**을 뽑지 않는다

이번 회차의 가장 큰 발견이다. 처음에는 "배포본 스크립트에만 있는 것"으로 적었는데,
ECM 전문을 받아 보니 **eCoDY 에 그대로 있었다.**

`patch_Dcm_common.py` 머리말이 선언한 7가지 중 5가지가 페이지에 없었다. 그 5가지를
ECM 에서 찾아보니:

| 스크립트 항목 | eCoDY 에 있나 | 어디 |
| --- | --- | --- |
| `DcmDspSecurityMaxAttemptCounterReadoutTime: 10` | ⭐ **있다** | SAG `210284000` **3.3.3.1 DcmDspSecurity** |
| `PMem_Driver`(`VOID`, `StartUp`, Index 0, Used true) 를 `EcuMDriverInitListTwo` 에 추가 | ⭐ **있다** | SAG `210284000` **3.3.5.2 Ecud_EcuM.arxml (R44)** |
| `DCM_FOTA_USED` / `_FBL` | **판정 불가** | IM `221450176`·`221451307` 이 **404**(`authorized: false`) — 권한 없음 |
| `UDS_ON_IP` 의 `P2StarServerAdjust = 3.5` | 확인한 3개 문서엔 **0건** | 다른 문서에 있을 수 있다 |
| `DcmTaskTime = 0.005` (R44) | 확인한 3개 문서엔 **0건** | 같다 |

**원인.** SAG `210284000` 은 설정 변경이 `3.3.1`(SCons) ~ `3.3.5`(Ecud_EcuM) 로 여러 절에
나뉘어 있는데, 페이지는 **`3.3.1` 한 절만 담았다.** 참조 가이드를 **링크로만** 걸고 그 안쪽
설정 변경 절을 뽑지 않는다.

### 모니터 스킬 보완 규격 — 페이지에 **참조 링크 원장**을 싣는다

사용자 방침(2026-11-06) — *"이런 링크 정보를 페이지 작성시 넣어 주면 좋지"*.
페이지가 링크를 이미 담고 있으면 이 스킬이 다시 찾아 헤맬 일이 없다. `ecody-ims-patch-monitor`
에 요청할 것은 두 가지다.

**① 참조 가이드의 설정 변경 절을 전부 수확한다.**
가이드(SAG·IM)를 링크로만 걸지 말고, 그 문서 안의 설정 변경 절(`3.3.x` / `2.1.1.x` 꼴,
표 머리가 `Location | Description | Image`)을 **전수로** 가져온다. 당사 해당 여부를 모르는
조건부 항목은 빼지 말고 **"조건: …, 당사 해당 여부 미판정"** 으로 적는다 — 빼면 작업자가
패치를 돌린 뒤에야 설정이 바뀐 것을 발견한다.

**② 못 연 문서에 제목과 출처를 붙인다.**
페이지 §5 가 `🔴 404 + 페이지 id` 만 적고, 푸터 `ECM-MISSING` 도 **번호만** 준다. 그래서
"이게 무슨 문서였고 누가 가리켰는지"를 매번 다시 찾아야 한다. **문서 제목 + 가리킨 출처 +
확인 날짜**를 함께 적으면 그대로 일감 §6 "받지 못한 자료"로 옮길 수 있다.

```
🔴 364422955 [MCAL 보증 범위 안내] — 티켓 본문 링크, 2026-11-06 404(authorized:false)
```

**반영 상태 (2026-11-06)** — 위 둘을 `ecody-ims-patch-monitor/references/page-format.md`
§3.1·§5 에 넣었다. 다음 회차 페이지에서 실제로 담겼는지 확인한다.

### 페이지가 맞았던 것 — 내가 페이지를 의심한 쪽이 틀렸다

| 내용 |
| --- |
| `EcuMDriverInitItemIndex` 를 페이지는 `55` 로 적었지만 **"중복 없는 순차 값이면 된다"는 말을 함께 담았다.** IM `2.1.1.5` 원문이 `중복되지 않는 순차적인 Index 설정 함 / 본 가이드에서는 42로 설정 함` 이다 — 42도 55도 예시다. 배포본의 `reindex_init_list()` 는 **확증**이었을 뿐, 배포본 없이도 eCoDY 만으로 알 수 있었다. 전태인씨 #49690 이 `index=55` 를 그대로 적은 것은 **IM 을 열지 않았기 때문**이다 |
| `ECUM_CAUSE_DCM` 의 `EcuMShutdownCauseId` 도 같은 꼴("중복되지 않는…")이다. **번호는 베끼지 말고 비어 있는 값을 쓴다** |

### 읽을 때 걸린 함정 — `ecm_api.py read` 는 기본값에서 본문을 자른다

처음 키워드 검색에서 위 두 항목이 **0건으로 나왔다.** 출력 말미에 `(이하 18,899자 생략)` 이
붙어 있었기 때문이다. 그대로 "eCoDY 에 없다 → 구조적 한계" 로 보고했으면 **틀린 결론을
스킬에 박았을 것이다.**

**ECM 문서에서 "없다"를 말하려면 `--max` 를 올려 전문을 받고 생략 표시가 없는지 확인한다.**

```bash
python ../ecody-search/scripts/ecm_api.py read <id>... --max 400000 --out "<스크래치>/ecm_full.txt"
grep -c "이하 .*자 생략" "<스크래치>/ecm_full.txt"   # 0 이어야 전문이다
```

## 다음 회차에서 먼저 볼 자리

위에서 나온 유형이 반복되는지부터 본다.

- [ ] Validation 산출물(`ruleID.csv` 등)이 첨부에 들어 있나 — 없으면 사용자에게 요청
- [ ] Generate 로그의 에러가 페이지 §3.3·§4 와 맞나
- [ ] 페이지 §2.5 가 적은 "못 본 것"이 실제로 그것뿐인가 (403·404 재시도)
- [ ] 꼬리표에 없는 연결 자료가 IMS 에 있나
- [ ] **`manifest["scripts"]` 의 스크립트 머리말을 다 읽었나** — 설정 변경이 페이지보다 많을 수 있다
- [ ] **`_harmonize/` 폴더가 있나, manifest 가 그것을 부르나** — 안 부르면 수동 실행이다
- [ ] 스크립트 머리말의 `Reference:` ECM URL 이 페이지에 들어 있나
- [ ] **참조 가이드(SAG·IM)의 안쪽 설정 변경 절을 페이지가 담았나** — 링크만 걸려 있으면 열어서 전수로 센다
- [ ] ECM 전문을 받았나 (`--max` 올리고 "자 생략" 표시가 0 인지) — 잘린 본문으로 "없다"고 하지 마라
