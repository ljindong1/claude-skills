# 일감 꼴

ASEC 에서 실제로 쓰이고 있는 꼴이다. 근거 일감 번호를 함께 적어 뒀으니, 의심스러우면
`redmine.py issue <번호>` 로 직접 보라.

## 0. 두 층이 있다

ASEC 의 패치 일감은 두 층으로 운영된다. 이름은 **실제 제목 그대로** 부른다 — 비유를
쓰면 읽는 사람이 무슨 말인지 모른다.

| 부르는 이름 | 실제 제목 | 하나당 | 예 |
| --- | --- | --- | --- |
| **회차 일감** | `[R44][<차종>/<제어기>][<구분>][V<x>] Delivery_Patch` | 패치 한 회차 | #48891 |
| **적용 건 일감** | `[<차종>][<제어기>] SWP 모듈 패치 적용 건` | 제어기 하나 | #49002 |

적용 건 일감은 **버전이 제목에 없고**, 본문에 그 제어기의 회차 일감 번호를 목록으로
걸어 둔다. 평가 결과 표와 PR 목록도 거기 모인다. 레드마인의 상위/하위 일감 기능이
아니라 **본문에 번호를 적어 둔 형태**다.

회차 일감만 쌓이면 "이 제어기에 지금까지 무엇이 들어갔나"를 볼 곳이 없다. 그래서
회차 일감을 만들 때마다 적용 건 일감에 한 줄을 더해야 한다.

## 1. 제목

```
[R44][<차종>/<제어기>][FBL][V<x>][APP][V<y>] Delivery_Patch
```

| 경우 | 예 | 근거 |
| --- | --- | --- |
| FBL·APP 함께 | `[R44][HE1i/PSU][FBL][V3.0.19][APP][V3.0.29] Delivery_Patch` | #48891 |
| APP 만 | `[R44][HE1i/PSU][APP][V3.0.27] Delivery_Patch` | #48881 |
| FBL 만 | `[R44][LT2/TPMS RF Receiver][FBL][V2.1.10] Delivery_Patch` | 위 꼴에서 APP 블록을 뺀다 |

차종·제어기 표기는 **그 제어기의 프로필을 따른다**. IMS 티켓 제목이 `BJ/TPMS` 라도 당사 적용
대상이 LT2 면 사내 일감은 `LT2/TPMS RF Receiver` 다 — 티켓 제목을 그대로 베끼지 마라.

## 2. 본문 골격 — 회차 일감

`swp-delivery-patch/references/templates.md` §1 과 같다. #48891 이 이 꼴로 되어 있다.

```

### 2.6 HAE 확인 필요

(첨부 폴더에서만 나온다 — 페이지에는 없다)

(원 일감, 직전·선행 일감, IMS, ECM 가이드, 정리 문서 링크)

[할일] [Delivery_Patch] [SWP] [<구분>] [<모듈>] [<차종>]
```

§6 을 빼먹지 마라. `swp-delivery-patch` 는 이 일감과 **사용자가 그때 넘기는 참조 자료**를
함께 들고 돈다. 본문이 로그 전문을 담을 필요는 없지만, **어느 파일의 어디를 보면 되는지**는
적혀 있어야 한다. 그리고 받지 못한 자료를 적어 두어야 작업자가 "자료가 없어 비운 칸"과
"빠뜨린 칸"을 구별할 수 있다.

```
## 6. 참조 자료 — 작업 착수 시 전달받는 것

- 정리 페이지 : <Confluence URL>
- 첨부 폴더 : <경로>
  - 배포본 : <폴더>/  (Doc/ReleaseNote, Doc/ModuleChangeList, Build/SCons.arxml,
    Configuration/Ecu/*.arxml, patch_tool/module_patch/<모듈>/...)
  - 빌드 로그 : <파일>
  - Generate 로그 : <폴더>/ (archive/ 는 직전 회차)
- 받지 못한 자료
  - <자료> : <사유 — 403/404/읽을 수단 없음>
```

절을 비워 두지 마라. 내용이 없으면 **그 절을 지운다**. `- 필요 시 기재` 같은 안내문이 남은
일감은 쓴 사람이 거기까지 생각하지 않았다는 뜻으로 읽힌다.

## 3. 본문 골격 — 적용 건 일감

회차 일감 여러 개를 묶는 상위 일감이다. 제목에 버전이 없다. 근거 #49002.

```
<차종><제어기> SWP 모듈 패치 적용 건
```

```
## 1. 요청 사항

<차종> <제어기>(FBL / APP)에 [R44][<계열>] SWP 모듈 패치를 차례로 적용하고,
버전마다 <평가> 결과를 남긴다.
모듈 패치 업무 프로세스(Delivery_Patch → Task → Change → commit · PR)에 따라
아래 패치 일감을 이 일감에 연결한다.

#### 모듈 패치 사항

(1) <모듈> <old> → <new> (<수평전개 키> — <차종> 은 <사유> 로 적용 대상)
(2) <VC 항목>
(3) HAE 확인 중 : <IMS 키> 질문 <n>건

## 2. 저장소 · PR
(구분별 저장소·작업 브랜치, PR 번호와 대상, 머지 순서 규칙)

## 3. 평가 결과
| 버전 | 결과 | 결과 폴더 | 일감 |

## 4. Change 일감
```

**회차 일감을 만들면 적용 건 일감에 줄을 더해야 한다.** 적용 건 일감만 있고 회차가 없거나, 회차만 있고
적용 건 일감에 안 걸려 있으면 나중에 추적이 끊긴다. 적용 건 일감이 없으면 만들지를 먼저 물어라.

## 4. 결과 코멘트 · 리뷰 회신 · IMS 질문

양식은 `../swp-delivery-patch/references/templates.md` 에 있다. 중복해서 적지 않는다.

| 쓸 것 | 어디 |
| --- | --- |
| 작업 결과 코멘트 | §2 |
| 리뷰어 지적 대응과 번호별 회신 | §2-1 |
| HAE 에 물을 질문 댓글 | §3 |
| 커밋 메시지 | §4 |

결과 코멘트는 **요약하지 말고 원문 전체를 사용자에게 보여 준 뒤** 등록한다.
남이 등록한 일감이면 등록하지 않고 초안만 넘긴다.
