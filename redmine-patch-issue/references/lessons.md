# 틀린 기록 — 실제로 이렇게 틀렸다

`SKILL.md` §2-2 의 규칙이 어디서 나왔는지를 적어 둔 곳이다. **S1 전에 한 번 읽는다.**
규칙만 읽으면 "알겠다" 하고 또 같은 실수를 한다. 틀린 장면이 기억에 남아야 멈춘다.

날짜를 꼭 적는다. 환경과 권한은 바뀌므로, 오래된 줄은 **다시 확인해야 하는 줄**이다.

## 가장 비싼 것 — 남이 한 것과 비교해서 메우려 한 것

| 언제 | 2026-11-06 |
| --- | --- |
| **무엇을 틀렸나** | 일감을 만든 뒤 전태인씨의 #49690·#49694 와 비교해 "내가 놓친 것"을 찾으려 했다 |
| **왜 틀렸나** | 비교는 **답지가 있을 때만** 가능하다. 사용자 말 — "남이 한것 비교하면 무슨 지랄이냐고 처음에 잘해야 한다고 이후는 내가 다 해야하니". 원래 이 일감을 처음 만드는 사람은 사용자이고, 다음 회차부터는 비교할 상대가 없다. 비교로 메울 수 있다고 생각하는 순간 **첫 판을 닫는 절차를 만들지 않는다** |
| **그래서** | 설정 변경 목록을 **출처 사슬로 닫는 절차**를 S3 에 넣었다(A ∪ B ∪ C). 그 절차는 비교 없이 혼자 돌아간다. 비교는 검증 수단이 아니다 — S4 |

아래는 그 절차를 만들게 된 개별 사건들이다.

## 출처를 끝까지 따라가지 않은 것

### 배포본 스크립트 머리말을 절차가 시키지 않아 우연히 봤다

| 언제 | 2026-11-06 |
| --- | --- |
| **무엇** | 정리 페이지 §3.1 은 설정 변경 **5건**을 적었는데, 배포본 `patch_Dcm_common.py` 머리말은 **7가지**를 선언하고 있었다 |
| **어떻게 찾았나** | 절차에 없었다. 다른 것을 보다가 눈에 걸렸다 — **다음에는 못 찾는다는 뜻이다** |
| **규칙** | S3 — `manifest["scripts"]` 의 스크립트 머리말을 **전수로 읽는다** |

### "여기에만 있다"를 찾아보지도 않고 적었다

| 언제 | 2026-11-06 |
| --- | --- |
| **무엇** | 위 5가지를 `page-gaps.md` 에 **"페이지가 원리상 알 수 없는 것(구조적 한계)"** 으로 적었다 |
| **사실** | ECM 을 찾아보니 둘이 그대로 있었다 — `DcmDspSecurityMaxAttemptCounterReadoutTime` → SAG `210284000` **3.3.3.1**, `PMem_Driver` → 같은 문서 **3.3.5.2**. 그 SAG 문서는 설정 변경을 `3.3.1`~`3.3.5` 여러 절에 나눠 담는데 페이지가 `3.3.1` 한 절만 가져온 것이었다 |
| **왜 나쁜가** | 구조적 한계로 적으면 **모니터 스킬을 고칠 기회가 영구히 닫힌다.** "고칠 누락"이면 다음부터 페이지만 봐도 되는데 |
| **규칙** | S6 — 구조적 한계로 분류하는 것은 "eCoDY 를 다 찾아봤다"는 주장이다. 뒤진 뒤에 가른다 |

### 참조 가이드를 링크로만 봤다

| 언제 | 2026-11-06 |
| --- | --- |
| **무엇** | 스크립트 머리말이 항목마다 `Reference:` ECM URL 을 걸고 있는데, 그 URL 을 열지 않았다. ECM `334008428`(`[Mode][R44][SAG]` `Ecud_Dcm.arxml` 변경 시 `Bswmd_BswM.arxml` 수동 설정)은 **정리 페이지에 아예 없는 문서**였다 |
| **규칙** | S3 — 머리말의 `Reference:` URL 을 전수 수확해 ECM 에서 열고, 그 문서의 설정 변경 절까지 센다 |

## "없다"를 잘린 출력으로 말한 것

| 언제 | 2026-11-06 |
| --- | --- |
| **무엇** | ECM 전문에서 `MaxAttemptCounterReadoutTime`·`PMem_Driver` 를 찾았는데 **0건**으로 나왔다 |
| **왜** | 출력 말미에 `(이하 18,899자 생략)` 이 붙어 있었다. `ecm_api.py read` 가 기본값에서 본문을 자른다. `--max 400000` 으로 전문 66,327자를 받아 다시 세니 나왔다 |
| **교훈** | **내가 자른 표본보다 도구가 조용히 자른 표본이 더 위험하다.** 내가 자른 것은 기억하지만, 도구가 자른 것은 전수인 줄 안다 |
| **규칙** | S5 — 전문을 받고 생략 표시가 0 인지 확인한 뒤에만 "없다"를 쓴다 |

## 1차 자료가 이미 말한 것을 내 발견으로 적은 것

| 언제 | 2026-11-06 |
| --- | --- |
| **무엇** | `EcuMDriverInitItemIndex` 가 페이지 `55` / 배포본 `33` / IM `42` 로 달라 **페이지를 의심**했다 |
| **사실** | 페이지는 `중복 없는 순차 값이면 된다` 를 **이미 담고 있었고**, IM `2.1.1.5` 원문도 `중복되지 않는 순차적인 Index 설정 함 / 본 가이드에서는 42로 설정 함` 이었다. 42 도 55 도 예시다 |
| **왜 나쁜가** | 1차 자료가 말해 둔 것을 내 발견으로 적으면 **정작 고쳐야 할 곳을 못 가리킨다.** 이 경우 고칠 곳은 페이지가 아니라 `55` 를 숫자로 적은 HAE 안내문과 그것을 베낀 일감(#49690)이었다 |

| 언제 | 2026-11-06 |

| **무엇** | "레드마인 첨부는 올릴 수 없다"가 스킬에 오래 적혀 있었다 |
| **사실** | `POST /uploads.json` 가 `HTTP 201` 로 토큰을 준다. 못 하는 게 아니라 **코드를 안 쓴 것**이었다. 그날 `redmine.py attach` 를 만들어 #49949 에 13.6MB 를 올렸다 |

## 전송이 터진 것 — 두 가지 기계적 함정

| | |
| --- | --- |
| **4바이트 문자** | 본문에 `🔴`(U+1F534)가 있어 `HTTP 500`. Redmine 설명 칼럼이 3바이트 `utf8` 이다. `⚠`·`⭐`·`✅` 는 안전하다. `field-map.md` §3-1 |
| **차량단계 공백** | 비우고 보냈다가 `422`. 표본 16건 중 1건이 비어 있어 "필수 아님"으로 결론 냈는데, 그 일감은 필드가 필수가 되기 전에 만든 것이었다. **표본으로 필수 여부를 판정하지 마라** |
| **CRLF** | 올라간 본문을 받아 고칠 때 줄끝이 `\r\n` 이라 `\n` 으로 쓴 찾을 문자열이 하나도 안 맞았다. 7곳 교체가 첫 줄에서 멈췄다. `field-map.md` §3-2 |
