# 무엇을 어디까지 추적하나

"끝까지 추적"을 무한히 두면 파일 수백 개에서 길을 잃는다. 경계를 규칙으로 못 박아 둔다.

## 1. eCoDY 정리 페이지에서 뽑을 곳

이 페이지는 `ecody-ims-patch-monitor` 가 만들어 구조가 고정돼 있다. 절 번호로 바로 간다.

| 페이지 | 쓰는 곳 |
| --- | --- |
| **맨 끝 꼬리표 한 줄** | 추적의 출발점. `IMS-PATCH-TICKET` · `IMS-UPDATED` · `IMS-PAIR` · `IMS-LINKED` · `IMS-MISSING` · `ECM-LINKED` · `ECM-MISSING` |
| §1 일감 개요 | 티켓·구분·모듈·SWP 버전·MCU·제어기 단계·harmonize 대상·적용 대상 |
| §1.1 경과 | 날짜별 경위. 재배포·개정 시점 |
| §2.1 버전 경로 | 시작·중간·목표 버전과 릴리즈 노트 |
| §2.2 중간 버전 | **티켓에 안 나오는 변경.** 설정 영향 판단이 여기 |
| §2.3 목표 버전 변경 | 결함·개선 목록 |
| §2.4 결함 상세 | **왜 받아야 하는가** + 재현 시나리오(→ 검증 TC) |
| §2.5 자료 공백 | → 본문 "HAE 확인 필요" 와 질문 초안 |
| §3.1 설정 변경 | → 본문 §2.2. 번호 항목 그대로 |
| §3.2 모듈 의존성 | 적용 전 확인할 다른 모듈 버전 |
| §3.3 새 Validation | 적용 후 뜰 수 있는 에러 — **예측이다.** 로그로 확인해야 사실이 된다 |
| §4 논의 | → 본문 §2.3 IA/VC. 결론과 **그 근거** |
| §5 함께 확인할 문서 | → 본문 §5 참고. 막힌 문서(403/404)는 §2.6 으로 |
| §6 적용 시 할 일 | → 본문 §1.1 진행 순서 + §3 검증 계획 |
| §7 첨부 파일 | 첨부 폴더와 대조. **재배포로 교체된 첨부가 있는지** |
| §8 참고 링크 | → 본문 §5 |

페이지가 **IM 절 번호를 정정해 둔 경우가 많다**(HAE 안내문의 번호가 어긋나는 것은 패턴이다).
본문에는 **페이지가 정정한 번호와 실제 URL** 을 쓴다.

## 2. 첨부 폴더 — 깊이 규칙

`scripts/harvest_attach.py` 가 이 규칙대로 돈다.

### 읽는다

| 대상 | 무엇을 얻나 |
| --- | --- |
| `patch_tool/patch_manifest.json` | **모듈·버전·기존 SWP 의 확정값.** 1차 출처 |
| `patch_tool/module_patch/**/*.py` | 패치가 **실제로** 손대는 경로. 설정 변경 안내의 교차검증. **manifest 의 `scripts` 에 든 것만** 본다 — patch_tool 은 모든 모듈의 스크립트를 동봉하고 대부분은 이번에 돌지 않는다 |
| `Doc/ReleaseNote/*.docx`, `Doc/ModuleChangeList/*.xlsx` | 배포 문서, 모듈 변경 목록 |
| **Harmonize 대조표** (`Automation_<날짜>.xls` 등) | ⭐ 당사 형상과 Harmonize 대상의 차이. `Difference` 열이 `Added`/`Deleted`/`Different` 를 말한다. **설정 변경 안내와 Harmonize 가 서로 반대로 작용하는 자리**가 여기서 드러난다 |
| `Build/SCons.arxml`, `Configuration/Ecu/*.arxml` | HAE 배포본 형상 — 설정 변경 대조 근거 |
| 빌드 로그 (`*build_log*.txt`, `*.log` 상위) | 빌드 성공·실패와 **치명 오류 원문** |
| `Generated/**/log/` 전부 + `archive/` | Generate·Validation 결과. `archive/` 는 직전 회차라 비교가 된다 |
| Validation 산출물 (`ruleID.csv` 등) | 페이지 §3.3 예측의 사실 확인 |

### 대조표를 읽는 법

머리글이 `BswM | Value | BswM | Value | Difference` 처럼 **양쪽 이름이 같다.** 어느 쪽이 현재
당사 형상이고 어느 쪽이 Harmonize 후인지 표가 말해 주지 않는다. 거꾸로 읽으면 "지워진다"와
"추가된다"가 뒤바뀌고, 그 해석이 그대로 일감에 적혀 작업으로 간다.

**그러나 이것은 사용자에게 물을 일이 아니다. 넘겨받은 자료로 확인할 수 있다.**

| 순서 | 확인법 |
| --- | --- |
| 1 | **`Summary` 시트를 끝까지 읽는다.** `Removed Container :` / `Created Container :` 목록과 `Apply Done` 이 있으면 그것이 답이다 — 무엇을 지우고 무엇을 만들었는지 이름까지 적혀 있다 |
| 2 | **당사 고유 설정이 어느 쪽에 있는지 본다.** 차종 전용 CAN·Rte 항목(`*_LCAN_*` 같은 것)은 배포본에 없다. 첨부 폴더에 당사 형상과 배포본 arxml 이 **둘 다** 있으니 `<SHORT-NAME>` 으로 대조하면 된다 |
| 3 | **이미 일어난 빌드·Generate 결과와 맞물리는지 본다.** 대조표의 차이가 그 뒤 빌드 오류를 설명하면 방향이 맞은 것이다 |

셋을 다 해 보고도 갈리면 그때 단서를 근거로 제시하고 사용자에게 묻는다. 먼저 묻지 마라.

### 대조표는 예상이 아니라 기록일 수 있다

`Apply Done` 이 있으면 **이미 적용된 것**이다. 그러면 "Harmonize 를 돌리면 ○○ 가 날아갈
위험이 있다"고 쓰면 안 된다 — 이미 날아갔거나 이미 복구됐다. 두 가지를 더 확인하라.

| | |
| --- | --- |
| 지워진 것이 **이후 형상에 되살아나 있나** | 있으면 작업자가 되돌린 것이다. 소실이 아니라 판단의 기록이다 |
| 만들어진 것이 **설정 변경 안내와 충돌하나** | 안내가 "삭제"라고 한 것을 Harmonize 가 만들면, **다시 돌릴 때마다 또 생긴다.** 이 성질은 일감에 반드시 적는다 — 적지 않으면 다음 사람이 같은 자리에서 또 막힌다 |

### 목록만 — 필요해지면 그때 펼친다

모듈 소스(`Static_Code/Modules/**/*.c|h`), `.jar`, `.epd`, UM `.pdf`.
수백 개가 되고, 일감 본문에 들어갈 일이 거의 없다. **본문에서 근거로 필요해지면 그 파일만** 읽는다.

### 멈춘다

| 상황 | 하는 일 |
| --- | --- |
| 중첩 압축(`.zip`/`.7z`/`.z01` 등)을 찾았다 | 사용자에게 알리고 전개 여부를 묻는다. 자동 전개하지 않는다 |
| 암호 걸린 압축 | 사용자에게 암호를 묻는다. 배포본 PW 는 메일로 온다 |
| 변환까지 해 봐도 못 읽는다 | **"읽지 못했음 + 왜"를 결과에 남기고** 넘어간다. 조용히 빠뜨리지 않는다 |

### 안전

넘겨받은 폴더는 **외부 자료**다.

- 안의 `.py`(수백 개)·`.bat`·`.jar` 은 **읽기만 하고 실행하지 않는다**
- 스크립트는 폴더 밖에 두고 **경로를 인자로 넘긴다**
- `python -I` 로 돌린다 — 폴더 안에 `json.py` 가 있으면 `import json` 이 그것을 집는다

## 3. 검증 모드 — eCoDY IMS·ECM 직접 추적

### 왜 하나

**목표 상태는 정리 페이지만 보는 것이다.** 지금 IMS·ECM 을 함께 두드리는 이유는 일감 때문이
아니라 **페이지가 무엇을 놓치는지 알아내 `ecody-ims-patch-monitor` 를 고치기 위해서**다.
각 경로가 아직 처음 돌아가는 중이라 서로를 받쳐 준다.

### 무엇을 보나

| | |
| --- | --- |
| 403·404 로 막혔던 자료 | **매번 다시 두드린다.** 권한은 풀린다(링크 수정으로 풀린 실제 전례가 있다) |
| 본문에 인용할 원문 | 요약이 아니라 원문. 특히 HAE 답변 문구 |
| 페이지 절과 IMS·ECM 실제 내용의 대조 | 빠진 절, 빠진 항목, 꼬리표에 없는 연결 |

**기준시각 이후의 새 댓글은 감시 대상이 아니다.** 보통 그 댓글은 내가 분석한 뒤 올린 것이거나,
다음 회차에 페이지가 갱신되며 들어온다.

### 어떻게

```bash
python ../ecody-search/scripts/ims_api.py read <티켓키>
python ../ecody-search/scripts/ecm_api.py read <페이지id>
python ../ecody-search/scripts/ims_api.py search --jql "<JQL>"
```
토큰과 크롬 폴백은 `ecody-search` 규약을 그대로 따른다. eCoDY 는 **읽기 전용(GET)** 이다.

### 끄는 기준

연속 **3회차** 동안 새 누락 유형이 나오지 않으면 검증 모드를 기본에서 뺀다.
그 뒤로는 **새 모듈·새 차종·페이지 양식 변경** 때만 돌린다.

이 기준을 적어 두는 이유는 "한시"가 저절로 영구가 되는 것을 막기 위해서다.
누락이 더 안 나온다면 페이지를 믿어도 된다는 뜻이고, 그게 원래 가려던 곳이다.

## 4. Redmine 선례 — 양식만, 내용은 아니다

| 쓴다 | 쓰지 않는다 |
| --- | --- |
| 제목 꼴, 본문 절 구성 | **같은 패치의 일감 본문** |
| 사용자정의 필드의 쓰이는 값 | |
| 직전 회차 번호, 적용 건 일감 번호 | |
| 그 프로젝트의 상태 전이 규칙 | |

같은 패치를 다른 사람이 먼저 해 둔 것이 있어도 **그것은 답지다.** 베끼면 그 사람이 빠뜨린
것까지 물려받는다. 그리고 비교할 거리가 없어진다 — 따로 만들어 나란히 놓고 봐야 양쪽의
누락이 드러난다.

조회는 ASEC 범위를 1순위로 하되, 양식 근거가 부족하면 다른 프로젝트 선례도 본다.
**단 필드값은 ASEC 것만 쓴다** — 프로젝트마다 쓸 수 있는 값이 다르다.
