Redmine 이 사내망에 있어 Claude Code CLI(사용자 PC, 사내망) 전용이며, 사내망 밖에서는 본문 조립까지만 하고 전송은 보류한다. 일반 Redmine 조회·등록은 redmine-issue, 실제 패치 적용 작업은 swp-delivery-patch, 정리 페이지 생성·갱신은 ecody-ims-patch-monitor 담당이다.

# SWP Delivery_Patch 일감 (ASEC)

**입력 하나 → 산출물 하나.**

| | |
| --- | --- |
| 입력 | eCoDY 패치 정리 페이지 URL (Confluence `mobaseasec4`) — **대표 1 장** |
| 입력 (주면) | **로컬 작업 폴더** — ⭐ **HAE 가 보낸 것은 읽고, 우리가 만든 것은 가리킨다** (§5 S1.5) |
| 산출물 | Redmine 일감 **1 개** (구분이 둘이면 각각 1 개) |

---

## 1. 이 일감은 보고서가 아니라 작업 지시서다

작업자는 이 일감 **하나만 띄워 놓고** 패치를 진행한다. 그 전제에서 네 가지가 따라온다.

| 원칙 | 뜻 |
| --- | --- |
| **작업 시간 순서로 배열한다** | 문서 분류 순서가 아니다. 위에서 아래로 한 번 읽으며 손이 움직여야 한다. 행동하지 않는 것은 아래로 내린다 |
| **추측으로 칸을 채우지 않는다** | 모르는 것은 **`Q` 번호를 붙여 "확인할 것"** 으로 남긴다. 모른다고 적힌 일감은 고칠 수 있지만, **그럴듯하게 틀린 값이 적힌 일감은 아무도 의심하지 않는다** |
| **현재 값은 적지 않는다** | 일감을 쓰는 시점과 작업하는 시점의 형상이 다르다. "우리 값은 55" 를 박으면 틀린 값이 확정으로 남는다. 대신 **"어떻게 확인하는지"** 를 적는다 |
| **자료에 없으면 일감에도 없다** | 메우려 들지 않는다. 없다는 사실을 `Q` 와 §10 에 적어 **"자료가 없어서 빈 칸"** 과 **"빠뜨린 칸"** 을 구별해 준다. 자료는 정리 페이지와 **사용자가 준 로컬 폴더**이고, 거기서 나온 것은 **출처를 밝혀** 넣는다 |

### 복사하지 말고 가리킨다

**정리 페이지가 정본이고 일감은 지시서다.**

| 본문에 넣는다 | 넣지 않는다 |
| --- | --- |
| 파일·컨테이너 경로, 바꿀 값, 근거(eCoDY 문서 id·절) | 페이지 문단 전재, arxml 내용 |
| **판정과 결론** | 거기 이르는 왕복 기록 — 부록을 가리킨다 |
| 참조 자료의 **위치** | 그 자료의 내용 |
| **받지 못한 자료**와 왜 못 받았는지 | — |

## 2. 하지 않는 것

| 하지 않는다 | 누구 일인가 |
| --- | --- |
| **3-way 판정** (HAE 이전/현재 형상과 당사 설정 대조) · 로그 해석 · 생성물 diff · 빌드 검수 | `swp-delivery-patch` |
| 당사 arxml 의 **현재 값을 읽어 본문에 박기** | 아무도 — 일감에 적지 않는다 (§1 "현재 값은 적지 않는다") |
| eCoDY-IMS·ECM 직접 수확, 근거 문서 열어 절 읽기 | `ecody-ims-patch-monitor` — 그 결과가 정리 페이지다 |
| 과거 회차 일감과 대조 | 요청받을 때만, 별도로. 산출물은 일감 **댓글** |
| 남이 등록한 일감 수정 | 코멘트 초안만 만들어 사용자가 올린다 |
| 첨부 올리기 | 본문에 페이지 링크를 적으면 끝난다. **사용자가 요청할 때만** |

⚠ **과거 회차 일감을 베끼지 않는다.** 같은 패치를 먼저 해 둔 일감은 **답지**다. 베끼면 그 사람의 누락까지 물려받고, 회차를 가로지르는 이야기가 본문에 섞이면 **이번 지시와 지난 미결이 구별되지 않는다** — 그건 댓글이 맞다.

## 4. 일감을 만드는 곳과 필드

**프로젝트는 `mobilgene Classic - MOBASE ASEC`(`mobilgene-classic-mobase-asec`, id **1201**) 한 곳이다.** 다른 프로젝트 요청은 거부하고 `redmine-issue` 로 안내한다. 사용자의 패치 회차 일감은 2026-09 파견 이후 **전부 이 프로젝트**에 있다(#47967 · #48881 · #48891 · #48909 · #49479 · #49949 · #49951).

### 4.1 추적과 제목

**추적은 `Task`(id 9) 다.** 이 프로젝트에 켜진 추적은 넷뿐이다 — `Defect(SWP_Ori)`(1) · `Task`(9) · `회의`(5) · `Information`(14). **`Delivery_Patch` 추적도 `Change` 추적도 여기엔 없다.** 제목 끝의 `Delivery_Patch` 는 추적이 아니라 **정형 문구**다.

> 사내 규칙상 `Delivery_Patch` 추적은 **플랫폼이 내보내는 쪽**의 것이고 받아서 적용하는 쪽은 `Task` 다. 협업 프로젝트에서는 이 구분이 켜져 있지 않아 **전부 `Task`** 로 쓴다.

**제목** — 프로젝트 공지(`일감 템플릿 > 템플릿 옵션 설정 > 일감 제목 룰 공지`)는 `[차종][제어기] 일감 제목`(유형 Task)이고, 패치 회차는 그 위에 릴리스와 구분·버전을 얹은 형태가 선례로 굳어 있다.

```
[R44][<차종>/<제어기>][<구분>][V<x>] Delivery_Patch
```

예 — `[R44][LT2/TPMS RF Receiver][APP][V2.1.11] Delivery_Patch` · `[R44][HE1i/PSU][APP][V3.0.28] Delivery_Patch`

- ⚠ **`— 모듈 버전 → 버전` 같은 접미를 붙이지 않는다.** 선례 6 건 모두 `Delivery_Patch` 로 끝난다. 모듈 승급은 본문 §1.1 이 담당한다.
- 두 구분을 한 일감에 묶을 때만 `[FBL][V<x>][APP][V<y>]` (선례 #47967 · #48891 · #49479).
- 차종·제어기 토큰은 **기존 일감 제목을 복사해 쓴다.** 제목 대괄호가 이 인스턴스의 유일한 검색 키라서 오탈자 하나로 필터에서 빠진다. 확인된 표기 — 차종 `LT2` · `BJ1` · `HE1i` · `NQ6e`, 제어기 `TPMS RF Receiver` · `PSU` · `CFC` · `MKBD`.

### 4.4 등록한 뒤

- **`relates` 로 묶는다** — 짝 구분 일감, 그리고 그 제어기의 상위 "SWP 모듈 패치 적용 건"(PSU 는 #49002 가 그 자리다). 상위 일감이 없는 제어기면 **만들지 말고 사용자에게 알린다.**

- 본문에서 다른 일감은 `#49951`, 제목까지 보이려면 `##49951`, 특정 댓글은 `/issues/49951#note-2`, 이 일감의 첨부는 `attachment:"파일명"` 으로 가리킨다.
- 첫 등록이 성공하면 그 제어기의 확정값을 `references/projects/<제어기>.md` 에 적어 둔다(다음 회차에 조회를 줄인다).

## 5. 순서 — 셋이다

### S1. 페이지 읽기 — 대표 + 부록 **전부**

```
getConfluencePage(pageId=<대표>, contentFormat="markdown")
```

페이지는 **대표 1 장 + 부록 여러 장** 구조다. ⭐ **대표만 읽으면 변경 상세가 통째로 빠진다** — 그것이 부록에 있다.

읽을 부록은 **맨 끝 꼬리표의 `IMS-SUBPAGES`** 가 알려 준다. **전부 읽는다** — 이름이 회차마다 다를 수 있으므로 꼬리표의 id 를 쓴다.

| 꼬리표 | 쓰는 곳 |
| --- | --- |
| `IMS-PATCH-TICKET` | 제목 · §0 · §10 |
| ⭐ `IMS-SUBPAGES` | **읽을 부록 목록. 전부 읽는다** |
| `IMS-PAIR` | 짝 구분 일감 (§0 · §10) |
| `IMS-MISSING` · `ECM-MISSING` | **받지 못한 자료** → `Q` 번호와 §10 (사유·날짜까지) |
| `IMS-UPDATED` | 페이지가 어느 시점 기준인지. **그 뒤 변화는 모른다** — 본문 맨 끝에 적는다 |

⚠ **페이지 구조가 바뀌면 이 표가 아니라 꼬리표를 믿는다.** 꼬리표는 `ecody-ims-patch-monitor` 가 유지한다.

### S1.5 로컬 작업 폴더 — 사용자가 주면

⭐ **경계는 하나다 — HAE 가 보낸 것은 읽고, 우리가 만든 것은 가리킨다.**

| | 무엇 | 왜 |
| --- | --- | --- |
| **읽는다** | `patch_manifest.json` — 모듈·버전·**실제로 실행되는 스크립트 목록** | 도구가 하는 자리와 사람이 하는 자리를 가르는 **유일한 자료**다. 안 보면 그 칸을 채울 수 없다 |
| **읽는다** | 패치 스크립트의 **머리말**(선언된 처리 목록) | ⭐ **HAE 설정 변경 안내가 완전하지 않다.** 안내에 없고 스크립트에만 있는 항목이 나온다(선례: 안내 6 + 스크립트 5 = 11). 그 5 개는 정리 페이지만 보면 **일감에 아예 없다** |
| **읽는다** | `Doc/` · 릴리즈 노트 · zip 내 `.arxml` 의 **용도**(적용본인지 참고용인지) | §2 준비와 §3 변경 지도의 근거 |
| **가리킨다** | Generate 로그 · 빌드 로그 · 당사 arxml · Harmonize 대조표 | **쓰는 순간 낡는다.** 해석·판정은 `swp-delivery-patch` 몫이다 → §10 에 **경로만** |

- 읽어서 넣은 항목에는 **출처를 적는다** — `배포본 patch_tool/patch_manifest.json` 처럼. 정리 페이지에서 온 것과 구별돼야 한다.
- ⚠ **읽되 판정하지 않는다.** "스크립트가 이 처리를 선언한다" 까지가 이 스킬이고, "우리 형상에 어떻게 반영할지" 는 `swp-delivery-patch` 다.
- 폴더에 파일이 수백 개여도 **열 것은 위 네 줄뿐**이다. 나머지는 열 이유가 없다.

### S2. 본문 조립

목차와 각 절 규격은 **§6** 이다. 골격은 `references/body-template.md`, 완성 예시는 `references/example-MCP1001-199.md`.

### S3. 미리보기 → 승인 → 전송

`--yes` 없이 한 번 실행해 **미리보기만 출력하고 종료코드 2 로 멈춘 뒤**, 사용자가 **다음 메시지에서** 승인하면 같은 명령에 `--yes` 를 붙여 다시 실행한다. **한 턴에 둘을 연달아 실행하면 안전장치가 무의미해진다.** 종료코드 2 는 실패가 아니라 "확인 대기" 다.

미리보기에서는 칸마다 **출처 주석**(`← 대표 §1`, `← 부록 B.2-1`, `← 꼬리표 ECM-MISSING`)을 달고 **전송 본문에서는 뺀다.** 승인하는 사람이 "이 값이 어디서 왔나" 를 눈으로 확인할 수 있어야 한다.

전송 후에는 번호와 URL 을 전하고, 짝 구분 일감·직전 회차와 연결할지 묻는다.

## 6. 본문 규격 — 목차 0~10

★ **배열 원칙: 작업 시간 순서.** 그래서 "판정" 이 앞에 오고 "참고" 가 뒤로 간다.

⚠ **사내 본문 골격(`1. 목적 / 2. 업무 내용 / 3. 검증 계획 / 4. 참고 사항`)을 겉에 두르지 않는다.** 그 골격은 **보고 서식**이고 작업 순서·함정·완료 조건 같은 성질이 없다. 사내 가이드 본문도 "서식이 시스템으로 강제되지 않는다" 고 적고, 선례끼리도 갈린다(#49002 는 `1. 요청 사항 / 2. 저장소·PR / 3. 평가 결과 / 4. Change 일감`). 본체 전부를 `2. 업무 내용` 아래 `###`·`####` 로 묻으면 **한 창으로 작업하면서 보기 나빠진다** — 이 일감의 목적이 그것이다.

사내 양식에서 **받는 것은 제목·필드·완료일·상태 운영**(§4)과 아래 두 내용 항목이다.

| 절 | 하는 일 | 페이지의 어디서 |
| --- | --- | --- |
| **0. 한눈에** | 열자마자 보일 것 — 모듈·버전, SWP 버전, **군데 수**, Generate 후 생길 일, ⭐ **가장 위험한 단계**, 설정 밖(코드)에 닿는 것, **돌리지 않는 시험**, 짝 구분, 적용 대상(MCU·MCAL·제어기 단계). 끝에 **`[기입]` 칸** | 대표 §1 + 요약 박스 |
| **1. 목적** | ⭐ 1.1 **승급 모듈** — `모듈 기존버전 -> 신규버전` 목록. **의존 모듈도 적고 무엇 때문에 따라 올라가는지 괄호로 밝힌다**(사내 관행). 근거 수평전개·적용 일감이 사내에 있으면 `#번호` · 1.2 **받는 이유 셋**(한 줄씩) · 1.3 ⭐ **결함별 "우리에게 해당하는가" 판정표** | 대표 §1·§2 + 부록 A |
| **2. 작업 전 준비** `P1~` | 배포본 확보(**재배포 여부·대조**), 압축 PW 위치, 안내 댓글 **수정 이력**, zip 내 arxml 의 용도, 기준 형상, 의존 모듈, 브랜치 | 대표 §4 앞머리 + 부록 A·D |
| **3. 변경 지도** | ⭐ **파일 단위 요약표만.** 파일 / 군데 / 무엇을(한 줄) / 어느 단계 + ☐. **"다 했나" 를 세는 자리다** | 부록 B 의 군데 수 표 |
| **4. 작업 단계** `S1~` | ⭐ **본체.** 고정 순서와 **왜 고정인지**. 각 단계는 아래 4 요소 | 부록 B 파일별 소절 + harmonize 순서 |
| **5. 멈춰서 확인할 것** `Q1~` | 불확실한 것 / **어떻게 확인하나** / **무엇을 막나** / 틀리면 생기는 일 | 대표 "모르는 것" + 부록 A 의 자료 공백 |
| **6. Generate 후 Validation** | ⭐ **걸릴 가능성이 높은 것을 먼저**, 그 근거와 **선제 점검 대상**. 나머지는 조건만 한 줄 | 부록 B 의 Validation 절 |
| **7. 검증** | 7.1 돌릴 것 `V1~` · 7.2 ⚠ **돌리지 않을 것 `X1~` 과 사유** | 대표 "끝났다는 기준" |
| **8. 완료 기준** | ☐ 체크박스. §3 군데 수, `Q` 닫힘, ERR 기록, 빌드, 버전업, 짝 구분 동반, 종결 | 위 절들의 집계 |
| **9. 범위가 아닌 것** | **결론부터.** 왜 범위가 아닌지 + ⚠ **남은 위험**(철회된 것이 아님) | 부록 B "닿지 않는 것" + 부록 C |
| **10. 참고** | 정리 페이지·부록 링크, **근거 문서(절 어긋남 주의)**, 티켓, 연락처, **못 본 자료** | 부록 C·D + 꼬리표 |
| ⭐ **검색 태그** (무번호, 맨 끝) | 대괄호 키워드 3~5 개 — `[Delivery_Patch] [패치] [<모듈>] [<제어기>] [<구분>]`. 이 인스턴스에는 라벨·범주가 없어서 **제목과 이 절이 유일한 검색 키다**(사내 관행) | — |

`검색 태그` 바로 앞에 **페이지 기준 시각**과 "그 이후 변화는 반영되지 않았다" 를 한 줄로 적는다.

### 6.1 번호 체계는 셋뿐이다

| 번호 | 무엇 |
| --- | --- |
| `S1`, `S2`… | **작업 단계.** 본문의 뼈대 |
| `Q1`, `Q2`… | **멈춰서 확인할 것** |
| `V1~` / `X1~` | 돌릴 시험 / **돌리지 않을** 시험 |

⭐ **군데마다 ID 를 붙이지 않는다.** 군데는 **파일 단위로 세고**(§3), 가리킬 때는 단계로 가리킨다(`S2` 의 삭제). **번호 체계가 넷이 되면 표가 깊어지고 §3 과 §4 가 같은 내용을 두 번 적게 된다.**

`P1~`(준비)는 체크리스트 항목일 뿐이라 번호 체계로 세지 않는다 — 다른 절에서 `P` 를 가리키지 않는다.

⭐ **이 번호는 작업이 끝난 뒤 결과 보고의 키가 된다.** 작업자가 코멘트로 결론을 적을 때 `S4 완료` · `Q3 닫음 — 미사용` 처럼 **번호로 가리킨다.** 그래서 **한 번 매긴 번호는 바꾸지 않는다** — 중간에 하나가 빠지면 비워 두거나 맨 끝에 붙이고, 전체를 다시 당기지 않는다.

### 6.2 §3 변경 지도 — 요약 수준을 지킨다

```
| | 파일 | 군데 | 무엇을 | 단계 |
| ☐ | `Build/SCons.arxml` | 2 | `Compile/ASW`·`Compile/BSW` 의 `DefineOption` 에 `__GHS__` 추가 | `S5` |
```

| 넣는다 | 넣지 않는다 |
| --- | --- |
| 파일명 · 군데 수 · **한 줄 요약** · 단계 · ☐ | 전체 컨테이너 경로 · 상세 파라미터값 · 근거 문서 · 함정 |

그것들은 **§4 의 해당 단계**에 있다. 아래에 합계(`arxml N 개 · M 군데`)와 **"안내 밖 항목이 있었는지"**, 그리고 짝 구분과 **군데 수가 다르다는 경고**를 붙인다.

### 6.3 §4 작업 단계 — 네 요소를 지킨다

각 단계에 이 네 가지가 있어야 한다.

| 요소 | 왜 |
| --- | --- |
| **할 일** — 파일·컨테이너 **전체 경로**와 **바꿀 값**, 그리고 `> 근거 — <eCoDY 문서 id · 절>` | 작업자가 그대로 찾아갈 수 있어야 한다 |
| ⚠ **함정** | 이름이 어긋남, MCU 별로 갈림, 안내와 IM 이 다름 → 해당 `Q` 로 연결 |
| **단계 완료 조건** | "다음으로 넘어가도 되나" 를 스스로 판정하게 한다 |
| **안 하면** | 생략 유혹이 올 때의 판단 근거. 빠뜨림과 **잘못함**의 결과를 나눠 적는다 |

⭐ **HAE 안내 번호를 병기한다** — `*(안내 ③)*` 처럼. 우리는 **파일 단위**로 다시 묶지만(한 안내 항목이 두 파일에 걸치고 한 파일이 다섯 항목에 흩어진다), **HAE 와 대화할 때 쓰는 번호는 그쪽 번호**다. 병기하지 않으면 질문·회신에서 서로 다른 것을 가리킨다.

⚠ **재발할 수 있는 오류는 문구를 원문 그대로 적는다.** 요약하면 **검색이 안 된다** — 작업자는 `fatal error #2330: cannot open source file "Com.h"` 같은 문자열로 찾는다. 파일명·줄 번호까지 함께 둔다.

**근거는 eCoDY 문서만 적는다.** 우리 정리 페이지를 근거로 적지 않는다 — 사본을 가리키는 것이고 작업자에게 쓸모가 없다. 근거가 없으면 빈칸이 아니라 **`근거 미기재`**.

⭐ **"대상 없음" 도 적는다.** 안내에 있는데 우리 형상에 해당 없으면 **그 사실을 남긴다**(§9). 지우면 작업자가 안내와 대조할 수 없다.

⭐ **도구가 자동으로 하는 자리를 사람이 하는 자리와 섞지 않는다.** 섞으면 같은 자리를 두 번 고치거나, 반대로 "돌렸으니 됐다" 로 넘겨 빠진다. 사용자가 로컬 폴더를 줬으면 **S1.5 로 읽어 채운다.** 안 줬으면 **`배포본 patch_tool/patch_manifest.json 의 scripts[] 머리말에서 확인할 것`** 으로 **자리를 남긴다.** 절을 없애면 작업자는 거기를 봐야 한다는 것조차 모른다.

⭐ **harmonize 단계에는 되돌림 점검 자리를 둔다.** harmonize 는 **안내가 삭제를 요구한 컨테이너를 되살리고, 당사 고유 설정을 지운다.** 그래서 "harmonize 수행" 으로 끝내지 않고 ① **다시 생긴 것 재삭제** ② **지워진 당사 설정 복구** ③ **대조표로 전수 확인** 을 단계 안에 적는다 — **선별 수용이 기본이다.** 무엇이 생기고 지워졌는지의 **실제 목록은 작업 중에 대조표로 확인한다**(이 스킬은 대조표를 해석하지 않는다 — §2 · S1.5). 일감은 **그 자리를 남기는 것**까지다.

### 6.4 서식 제약

| | |
| --- | --- |
| ⚠ **4 바이트 문자 금지** | 색 이모지(🔴 👤 📌 💡)는 Redmine 전송을 `500` 으로 터뜨린다. 쓸 수 있는 것 — `⚠` `★` `☐` `※` `→` `✅`. 검사: `bad = {c for c in body if ord(c) > 0xFFFF}` |

## 7. 전송 전 점검

하나라도 걸리면 보내지 않고 고친다. **승인하는 사람은 이 점검을 대신해 줄 수 없다** — 그 사람은 내가 어느 칸을 어디서 집었는지 모른다.

- ☐ **부록을 전부 읽었나** — `IMS-SUBPAGES` 의 id 수와 읽은 수가 같나
- ☐ **`## 검색 태그` 가 맨 끝에 있나**
- ☐ §1.1 **승급 모듈**에 `기존 -> 신규` 가 있고 **의존 모듈과 그 이유**가 적혀 있나
- ☐ §3 의 군데 수가 **부록의 집계와 맞나**. 대표와 부록이 다르면 **부록이 정본**이고 차이를 사용자에게 알린다
- ☐ §3 이 **요약 수준**인가 — 경로·파라미터·함정이 §3 에 새어 나오지 않았나 (§6.2)
- ☐ §4 의 각 단계에 **네 요소**가 다 있나 (§6.3)
- ☐ 근거가 **eCoDY 문서**인가 — 우리 페이지를 근거로 적지 않았나
- ☐ 로컬 폴더를 읽었으면 그 항목에 **출처(`배포본 <경로>`)가 붙어** 있나 (§5 S1.5)
- ☐ **기존 본문을 베껴 온 문장이 없나** — 교체도 **스킬 기준으로 새로 쓴다** (§2 · §8)
- ☐ **로그·당사 형상 현재값이 본문에 박히지 않았나** — 경로만 §10 에 있나
- ☐ **현재 값을 사실로 박은 문장이 없나** — "확인 방법" 으로 적혀 있나
- ☐ 페이지에 없어서 비운 칸이 **`Q` 와 §10 에 적혀** 있나 — 조용히 비우지 않았나
- ☐ `IMS-MISSING`·`ECM-MISSING` 이 **사유·날짜와 함께** §10 에 있나
- ☐ **`[기입]` 칸이 비어** 있나
- ☐ **4 바이트 문자가 없나**
- ☐ **필수 열 개 필드가 다 찼나** (§4.2) — 특히 CF `99`·`101`·`108`·`109`·`110`
- ☐ **완료일이 공란인가** (§4.3) — 묻지도, 추측해 넣지도 않는다
- ☐ 예상을 사실처럼 쓴 문장이 없나

## 8. 멈춰야 할 때

| 상황 | 하는 일 |
| --- | --- |
| 페이지 URL 을 안 줬다 | **요청한다.** 다른 것으로 때우지 않는다. **이미 등록된 일감을 고치라고 할 때도 마찬가지다** — 본문의 정본은 정리 페이지이므로 그 URL 없이는 조립하지 않는다 |
| 대표와 부록의 군데 수가 다르다 | **부록을 쓰고** 차이를 알린다 |
| 같은 회차 일감이 **ASEC 에 이미 있다** | 중복이다. 새로 만들지 말고 **수정·코멘트를 제안**한다 |
| 배포본·로그를 함께 줬다 | §5 **S1.5** 로 간다 — HAE 가 보낸 것은 읽고, **로그·당사 형상은 §10 에 위치만** |
| ⭐ **이미 등록된 내 일감의 본문에 정리 페이지에 없는 사실이 적혀 있다** | **그 본문을 입력으로 쓰지 않는다.** 본문은 **스킬 기준으로 새로 쓴다** — 일감은 정본이 아니다. 남길 가치가 있는 사실이면 **정리 페이지나 `references/projects/<제어기>.md` 에 올리자고 사용자에게 알린다** (거기 올라가면 다음 회차에 자동으로 따라온다) |
| 배포본을 **분석·판정**해 달라 | 범위가 아니다 → `swp-delivery-patch` |
| 다른 프로젝트에 만들어 달라 | 거부하고 `redmine-issue` 로 안내 |

**HAE 에 물을 것이 남으면** 질문 초안을 함께 낸다. **예·아니오로 답할 수 있게** 쓰고 혼자 결론 내지 않는다.

## 9. 구분이 둘일 때 (FBL · APP)

**구분마다 일감을 따로 만들고 서로 번호를 걸어 둔다.**

⚠ **짝 구분의 페이지를 베끼지 마라.** 같은 모듈·같은 버전인데 설정 변경이 거의 겹치지 않은 전례가 있다 — `DefineOption` 이 APP 은 `__GHS__`, FBL 은 `DCM_FOTA_USED` 였고 군데 수도 **17 대 8** 이었다. **양쪽 페이지를 각각 읽는다.**

한 일감에 두 구분을 묶는 선례도 있다(제목에 `[FBL][V<x>][APP][V<y>]`). **사용자가 그렇게 요청할 때만** 묶는다.

| 일 | 어떻게 |
| --- | --- |
| 짝 구분이 나중에 왔다 | 일감을 따로 만들고 서로 번호를 건다 |
| 회차가 추가됐다 | 회차마다 새로 만든다 |
| **내가 등록한 일감이 옛 규격이다** | 본문을 **현재 규격으로 교체**한다(§6). 정리 페이지를 다시 읽어 조립하고, **본문에 있던 배포본 유래 사실은 출처를 밝혀 유지**한다. 교체 이유는 **댓글 한 줄**로 남긴다 — 이력만 보고도 왜 바뀌었는지 알 수 있게 |
| 작업이 끝났다 / 리뷰어가 지적했다 | 이 스킬의 범위가 아니다 — 그 작업을 하는 스킬이 기록한다 |
