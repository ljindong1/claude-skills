# SWP 패치 일감 (ASEC)

패치 하나를 두고 자료가 네 곳에 흩어져 있다 — eCoDY 정리 페이지, 넘겨받은 첨부 폴더,
eCoDY-IMS·ECM, 그리고 Redmine 의 과거 회차. 이 스킬은 그것을 모아 **일감 하나**로 만든다.

이 업무에서 사고는 "몰라서"가 아니라 **"짝 패치와 같겠지"** 하고 넘어가서 난다.
같은 모듈·같은 버전 패치인데도 FBL 과 APP 의 설정 변경이 거의 겹치지 않는 일이 실제로 있었다
(`DefineOption` 이 APP 은 `__GHS__`, FBL 은 `DCM_FOTA_USED_FBL`). 그래서 이 스킬의 중심은
본문을 예쁘게 쓰는 것이 아니라 **출처를 갈라 놓고 어긋나는 곳을 드러내는 것**이다.

## 0. 실행 환경 — 가장 먼저 판단할 것

Redmine 은 사설 IP(172.23.x.x)에 있다. **Claude Code CLI(사용자 PC 네이티브)에서만 도달한다.**
Cowork·claude.ai 웹은 샌드박스라 egress 프록시에 막힌다 (403 `blocked-by-allowlist`, DNS 실패, 타임아웃).

샌드박스로 판단되면 진단에 시간을 쓰지 말고 첫 응답에서 바로 안내하라:
**"이 세션은 사내망에 닿지 않습니다. Claude Code CLI 에서 실행해 주세요."**

| 쓰는 것 | 어디 |
| --- | --- |
| Redmine 통신 | `../redmine-issue/scripts/redmine.py` — 다시 만들지 않는다 |
| eCoDY IMS·ECM | `../ecody-search/scripts/ims_api.py`, `ecm_api.py` (`check/search/read`) |
| Confluence 페이지 읽기 | Atlassian MCP `getConfluencePage` (`contentFormat: markdown`) |
| 환경변수 | `REDMINE_URL`, `REDMINE_API_KEY`, eCoDY 토큰은 ecody-search 규약 |

## 1. 고정된 것 — 묻지 않는다

사용자 방침이다. 매번 묻지 말고 이 값으로 가라. 다른 프로젝트에 만들어 달라는 요청은 **거부**하고
`redmine-issue` 로 안내하라.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 프로젝트 | `mobilgene-classic-mobase-asec` (id 1201) | 사용자 방침 |
| 추적 | `Task` | ASEC 에는 `Delivery_Patch` 추적이 없다 — 제목 규칙으로만 쓴다 |
| 제목 | `[R44][<차종>/<제어기>][FBL][V<x>]…[APP][V<y>] Delivery_Patch` | #48891 |
| 일감검토자 (id 99) | `141` 이승빈 | ASEC 표본 15건 중 12건 |
| 일감완료자 (id 101) | `545` 이택구 | ASEC 표본 15건 중 8건 |
| SWP 계열 버전 (id 109) | `<FBL 목표> / <APP 목표>` | #48891 `3.0.19 / 3.0.29` |
| 본문 골격 | `references/issue-forms.md` | #48891 = swp-delivery-patch templates §1 |

**ASEC 의 추적·필드값은 다른 프로젝트와 다르다.** 같은 패치의 일감이 `AUTOSAR - mobilgene Classic`(337)
에도 있을 수 있는데, 거기는 `Delivery_Patch` 추적이 따로 있고 일감완료자도 다르다. 337 의 값을
그대로 옮기지 마라.

## 2. 입력 — 항상 둘을 받는다

| | 무엇 | 없으면 |
| --- | --- | --- |
| ① | eCoDY 패치 정리 페이지 URL (Confluence `mobaseasec4`) | 멈추고 요청한다 |
| ② | 패치 첨부 폴더 경로 (예: `D:\Mobase\패치업무\<제어기>_실기검증\…\<구분>_v<버전>(<IMS키>)\`) | 멈추고 요청한다 |

둘 중 하나로 때우지 마라. 페이지는 eCoDY 쪽 전부를 요약해 주지만 **빌드·Generate 결과를 모른다**.
첨부 폴더는 물증을 주지만 **왜 이 패치를 받아야 하는지를 모른다**. 둘이 서로를 메운다.

## 2-1. 이 일감을 누가 읽나 — 요구되는 정밀도

이 일감은 보고서가 아니다. **나중에 `swp-delivery-patch` 가 이 일감을 읽고 실제 작업을 한다.**
그 스킬은 본문에 적힌 경로로 파일을 찾아 고치고, 적힌 브랜치에 커밋하고, 적힌 항목마다
결론을 적어 결과 코멘트를 쓴다.

그래서 요구되는 것이 달라진다.

| | 보고서라면 | 작업 입력이므로 |
| --- | --- | --- |
| 설정 변경 | "설정 변경 반영" | **파일 · 컨테이너 경로 · 바꿀 값**까지 |
| 저장소 | 생략 가능 | **저장소 · 작업 브랜치 · PR 대상**이 반드시 있어야 한다 |
| 검토 항목 | 서술 | **번호**를 매긴다 (S11 에서 하나씩 결론을 단다) |
| 모르는 것 | "확인 필요" | **무엇을 어떻게 확인하는지**까지 |
| 빈칸을 메우면 | 기록이 틀린다 | **코드가 틀린다** — 다음 스킬이 그 값을 믿고 파일을 고친다 |

마지막 줄이 이 스킬에서 가장 중요한 제약이다. 추측으로 채운 칸은 여기서 멈추지 않고
저장소까지 흘러간다. **모른다고 적힌 일감은 고칠 수 있지만, 그럴듯하게 틀린 값이 적힌
일감은 아무도 의심하지 않는다.**

### 실물은 그때 사용자가 넘긴다 — 그래서 복사하지 말고 가리킨다

`swp-delivery-patch` 는 이 일감만 들고 돌지 않는다. **사용자가 참조 자료(정리 페이지, 첨부
폴더)를 함께 넘긴다.** 그러니 일감 본문이 로그 원문이나 arxml 내용을 통째로 담을 필요가 없다.

본문이 해야 하는 일은 **가리키는 것**이다 — 어느 파일의 어디를 보면 되는지, 그리고 받지
못한 자료가 무엇인지. 그래서 회차 일감에는 **참조 자료 절**이 반드시 들어간다
(`references/issue-forms.md` §2 골격의 마지막 절).

| 본문에 넣는다 | 본문에 넣지 않는다 |
| --- | --- |
| 파일·컨테이너 경로, 바꿀 값, 근거(IM 절·HAE 답변 날짜) | arxml 내용, 소스 전문 |
| 빌드·Generate 의 **판정과 치명 오류 몇 줄** | 로그 전문 |
| 참조 자료의 **위치**와 그 안에서 볼 파일 | 그 파일의 내용 |
| **받지 못한 자료**와 왜 못 받았는지 | — |

마지막 줄을 빼먹지 마라. 작업자가 "이건 자료가 없어서 비워 둔 것"과 "이건 빠뜨린 것"을
구별할 수 있어야 한다.

## 2-2. 서둘러 끝내지 않는다

이 일감 하나가 저장소를 고치는 작업으로 이어진다. **여기서 아낀 10분이 뒤에서 며칠이 된다.**
비싼 것은 오래 걸린 수확이 아니라 빨리 내놓은 틀린 칸이다. 토큰이나 시간을 아끼려고 단계를
건너뛰지 마라. 전수로 보라고 한 것은 전수로 본다.

급하게 끝내려 할 때 나오는 실패는 네 가지 꼴인데, 넷 다 뿌리가 같다 —
**그럴듯한 첫 답에서 멈추는 것.**

| 꼴 | 어떻게 들리나 | 대신 할 것 |
| --- | --- | --- |
| **너무 이르게 포기한다** | "읽을 수단이 없습니다", "자료가 없습니다" | 변환·우회·재시도를 다 해 본 뒤에 말한다 (`references/field-map.md` 의 "읽을 수단이 없다고 말하기 전에"). 포기한 파일이 결론을 바꿀 내용을 담고 있던 전례가 있다 |
| **손에 있는 답을 사람에게 떠넘긴다** | "이건 확인해 주세요" | 묻기 전에 **내가 가진 자료로 답이 나오는지** 먼저 본다. 넘겨받은 폴더에 당사 형상과 배포본이 **둘 다** 있는데 어느 쪽이 당사인지 묻는 식의 질문은 하지 않는다 |
| **예상을 사실처럼 쓴다** | "…될 수 있습니다", "…위험이 있습니다" | **이미 일어났는지 먼저 본다.** 로그와 형상이 있으면 예상을 사실로 바꿀 수 있다. 못 바꾸면 "확인 못 함"으로 적는다 |
| **없는 장벽을 세운다** | "이 값이 없으면 등록이 안 됩니다", "그건 안 됩니다" | 선언하기 전에 근거를 확인한다. 되는지 **직접 찔러 본다** — 쓰기 API 는 대개 부작용 없이 확인할 수 있다(업로드 토큰만 받아 보기, 미리보기로 멈추기) |

### "안 된다"를 문서에 박지 마라 — 그게 다시 나에게 근거로 읽힌다

가장 오래 가는 실수다. 한 번 실패한 것을 스킬에 "하지 않는다"로 적어 두면, 다음부터는 그
문서가 **근거처럼** 읽혀서 다시 시도하지 않는다. 처음엔 "시도했더니 안 됐다"였는데 문서에
들어가면 "안 되는 것"이 된다. 환경은 바뀌고, 권한은 풀리고, 애초에 다른 이유로 실패했을
수도 있는데 그걸 확인할 기회가 영구히 닫힌다.

**실제로 이렇게 틀렸다.** "레드마인 첨부는 올릴 수 없다"가 오래 적혀 있었는데, 확인해 보니
`POST /uploads.json` 가 `HTTP 201` 로 토큰을 준다. 못 하는 게 아니라 **코드를 안 쓴 것**이었고,
그래서 그날 `redmine.py attach` 를 만들어 #49949 에 13.6MB 를 올렸다. "안 된다"가 문서에
적혀 있던 동안 아무도 다시 확인하지 않았을 뿐이다.

그리고 **고친 문서도 금방 낡는다.** 위 문장을 "아직 구현하지 않았다"로 적은 지 20분 만에
구현해서 다시 고쳐야 했다. 능력이 바뀌면 **그 자리에서 문서를 고친다** — 나중에 하면
그 사이에 읽은 내가 또 틀린 말을 한다.

그래서 한계를 적을 때는 **세 가지를 함께** 적는다.

| 적을 것 | 왜 |
| --- | --- |
| **무엇이** 안 되는지 | "첨부가 안 된다"가 아니라 "`redmine.py` 에 올리는 코드가 없다" |
| **언제 확인**했는지 | 날짜가 없으면 다시 확인할 시점을 알 수 없다 |
| **못 하는 것**인지 **안 하는 것**인지 | 능력의 한계와 정책은 다르다. 정책이면 바꿀 수 있다 |

"안 된다"고 적힌 줄을 읽었을 때, **날짜가 오래됐거나 이유가 안 적혀 있으면 그 줄을 믿지 말고
다시 확인한다.** 문서는 그때 참이었던 것을 적어 둔 것이지 지금의 사실이 아니다.

그리고 **표본으로 결론 내지 않는다.** 로그가 44개면 44개를 다 보고, 대조표가 1,882행이면
1,882행을 다 센다. 앞 몇 줄만 보고 "에러 없음"이라고 쓰면 그 문장이 일감에 남아 사실이
된다. 수확 스크립트가 전수로 도는 이유가 이것이다.

질문을 넘기기 전에 스스로 물어라 — **"이 답이 내 손안의 자료에 있나?"** 있으면 찾아서
답하고 찾은 근거를 함께 보인다. 없을 때만 묻고, 물을 때는 **무엇을 이미 해 봤는지**
함께 말한다. 그래야 사용자가 같은 것을 또 해 보지 않는다.

## 3. 순서

### S1. 페이지 읽기

`getConfluencePage` 로 markdown 전문을 받는다. 이 페이지는 `ecody-ims-patch-monitor` 가 만든 것이라
**구조가 고정**돼 있다. 뽑을 곳은 `references/tracing.md` §1 에 적어 뒀다.
맨 끝 **꼬리표 한 줄**(`IMS-PATCH-TICKET: … · IMS-PAIR: … · ECM-LINKED: …`)이 추적의 출발점이다.

### S2. 첨부 폴더 재귀 수확

```bash
python -I scripts/harvest_attach.py "<첨부 폴더>" --out "<스크래치>/attach.json"
```

첨부 안쪽의 첨부까지 내려간다 — 배포본 안 `Doc/`(docx·xlsx), `patch_tool/module_patch/**/*.py`,
`Build/SCons.arxml`, `Configuration/Ecu/*.arxml`, 빌드 로그, `Generated/**/log/` 전부와 `archive/`.
깊이 규칙과 "읽는 것 / 목록만" 경계는 `references/tracing.md` §2.

넘겨받은 폴더는 **외부 자료**다. 안의 `.py`·`.bat`·`.jar` 은 읽기만 하고 실행하지 않는다.
스크립트는 폴더 밖에 두고 경로만 인자로 넘기며 `python -I` 로 돌린다 — 폴더 안에 `json.py` 가 있으면
`import json` 이 그것을 집는다.

### S3. 교차검증 1차 — 페이지 ↔ 첨부

**버전이 어긋나면 그 자리에서 멈춘다.** `patch_manifest.json` 의 모듈·버전·기존 SWP 가 1차이고
페이지가 2차다(우선순위는 `references/field-map.md` 맨 앞). 어긋났다면 한쪽이 낡은 것이고,
모르고 쓰면 틀린 일감이 영구히 남는다.

### S4. ASEC 선례

```bash
python scripts/find_precedent.py --controller "<제어기 키워드>" --out "<스크래치>/precedent.json"
```

얻을 것은 **양식과 필드값**이다. 직전 회차 일감 번호, 적용 건 일감, 필드 분포.
**같은 패치의 일감을 내용 출처로 쓰지 마라** — 다른 사람이 먼저 한 것이 있어도 그것은 답지다.
그 사람이 빠뜨린 것을 그대로 물려받게 된다. 내용은 ①②③④ 에서만 온다.

#### 무엇이 중요한 차이인가 — 선례와 달라도 올리지 않는 것

원래 이 일감을 **처음 만드는 사람은 사용자**다. 남이 먼저 한 것이 있는 것은 지금 연습
중이라서 생긴 일시적인 사정이고, 그 사람의 값이 기준이 되는 것이 아니다. 그러니 선례와
다르다는 사실 자체는 보고거리가 아니다.

가르는 선은 하나다 — **작업자가 그 값으로 코드를 고치나.**

| 중요하다 (어긋나면 코드가 틀린다) | 중요하지 않다 (나중에 채우거나 고치면 된다) |
| --- | --- |
| 파일·컨테이너 경로, 바꿀 값 | 저장소·작업 브랜치·PR 대상 — **일감을 먼저 만들고 나중에 추가한다** |
| 손으로 적으면 안 되는 값 (`index` 처럼 스크립트가 재계산하는 것) | 차량단계 — 단계가 넘어가면 그때 고친다 |
| 짝 구분과 **다른** 항목 | 담당자·검토자·완료자 |
| 패치 스크립트가 자동으로 하는 것과 그 조건 | 일감을 몇 개로 쪼갰나, 적용 건 일감이 어느 프로젝트에 있나 |
| IM 절 번호·버전처럼 **지금 확인 가능한 사실** | 제목의 괄호 순서 같은 표기 차이 |

오른쪽 칸이 선례와 달라도 **문제로 올리지 말고 묻지도 마라.** 왼쪽 칸만 본다.
비교해 달라는 요청에도 같은 기준을 쓴다 — 행정값을 나열하면 정작 코드를 틀리게 만들
항목이 묻힌다.

### S5. eCoDY 직접 추적 — 검증 모드

```bash
python ../ecody-search/scripts/ims_api.py read <티켓키>
python ../ecody-search/scripts/ecm_api.py read <페이지id>
```

**목표 상태는 페이지만 보는 것이다.** 지금 이것을 함께 돌리는 이유는 하나뿐 — 페이지가 무엇을
놓치는지 알아내 `ecody-ims-patch-monitor` 를 고치는 것이다. 규칙과 끄는 기준은
`references/tracing.md` §3, 지금까지 찾은 누락은 `references/page-gaps.md`.

403·404 로 막혔던 자료는 **매번 다시 두드려라**. 권한은 풀린다(실제 전례 있음).

**ECM 문서에서 "없다"를 말하려면 전문을 받아라.** `ecm_api.py read` 는 기본값에서 본문을
잘라 내고 말미에 `(이하 N자 생략)` 을 붙인다. 잘린 본문으로 키워드를 세고 "eCoDY 에 없다"
고 결론 내면 **그 틀린 결론이 스킬에 박힌다** — 2026-11-06 에 실제로 그럴 뻔했다.

```bash
python ../ecody-search/scripts/ecm_api.py read <id>... --max 400000 --out "<스크래치>/ecm_full.txt"
grep -c "자 생략" "<스크래치>/ecm_full.txt"   # 0 이어야 전문이다
```

그리고 **참조 가이드(SAG·IM)는 링크만 보지 말고 열어라.** 설정 변경이 `3.3.1`~`3.3.5`,
`2.1.1.x` 처럼 여러 절에 나뉘어 있고, 정리 페이지가 그중 한 절만 담은 전례가 있다
(`references/page-gaps.md` §2). 표 머리가 `Location | Description | Image` 인 절이 설정 변경이다.

### S7. 본문 조립

골격은 `references/issue-forms.md`, 어느 칸을 무엇으로 채우는지는 `references/field-map.md`.
**미리보기에만 칸마다 출처 주석**(`← manifest`, `← 페이지 §3.1 ⑥`, `← log_FW.log:2410`)을 달고
전송 본문에서는 뺀다. 승인하는 사람이 "이 값이 어디서 왔나"를 눈으로 확인할 수 있어야 한다.

HAE 에 물을 것이 남으면 **질문 초안**을 함께 낸다 — 양식은
`../swp-delivery-patch/references/templates.md` §3. 예·아니오로 답할 수 있게 쓰고, 혼자 결론 내지 않는다.

### S8. 미리보기 → 승인 → 전송

**내보내기 전 점검.** 미리보기를 보이기 직전에 한 줄씩 확인한다. 하나라도 걸리면 보내지
않고 고친다. 승인하는 사람은 이 점검을 대신해 줄 수 없다 — 그 사람은 내가 어디서 값을
집었는지 모른다.

- [ ] 칸마다 **어디서 왔는지** 말할 수 있나 — 못 하는 칸은 애초에 채우지 말았어야 한다
- [ ] "확인 필요"에 올린 것마다 **왜 모르는지**와 **어떻게 확인하는지**가 적혀 있나
- [ ] §6 에 **받지 못한 자료** 목록이 있나 — 없으면 "자료 없음"과 "빠뜨림"을 구별할 수 없다
- [ ] 예상을 사실처럼 쓴 문장이 없나
- [ ] 선례 본문을 베낀 칸이 없나 — 내용은 1차 자료에서만 온다
- [ ] 경로·컨테이너·값이 **작업자가 그대로 찾아갈 수 있는 형태**인가
- [ ] **다시 돌리면 되돌아가는 설정**(Harmonize 등)을 그 항목에 적었나
- [ ] 적용 건 일감에 더할 한 줄을 준비했나
- [ ] **첨부할 파일을 골라 뒀나**(S9) — §6 에 적은 자료가 첨부로도 가야 한다
- [ ] 본문에 **4바이트 문자(색 이모지)가 없나** — 있으면 전송이 500 으로 터진다 (`{c for c in body if ord(c) > 0xFFFF}`)
- [ ] **차량단계를 채웠나** — 비우면 422 다

`redmine-issue` 규약 그대로다. `--yes` 없이 한 번 실행해 **미리보기만 출력하고 종료코드 2로 멈춘 뒤**,
사용자가 다음 메시지에서 승인하면 같은 명령에 `--yes` 를 붙여 다시 실행한다.
한 턴에 둘을 연달아 실행하면 안전장치가 무의미해진다. 종료코드 2 는 실패가 아니라 "확인 대기"다.

전송 후에는 번호와 URL 을 전하고, 적용 건 일감·직전 회차와 연결할지 물어라.

### S9. 참조 자료 첨부

일감은 작업 지시서이고, 작업자는 **그 일감만 열어서** 일을 시작할 수 있어야 한다. §6 이
"어디에 무엇이 있다"를 적었다면 S9 는 그것을 **실제로 붙이는** 단계다. 넘겨받은 폴더 경로는
내 PC 의 것이고, 작업자나 리뷰어의 PC 에는 그 폴더가 없다.

ASEC 선례가 그렇게 한다 — #48891 은 배포본 zip·VC 결과·평가 산출물을 항목별 zip 으로 13개
붙였고, #49479 도 같은 꼴이다. 첨부 없는 회차 일감은 ASEC 에 없다.

**그래서 이 단계는 선택이 아니다.** 본문을 보냈으면 묻지 말고 이어서 붙인다 — 첨부가 빠진
일감은 작업자가 내 PC 폴더를 찾아 달라고 되묻게 된다.

```
python ../../redmine-issue/scripts/redmine.py attach <번호> \
  --file "<파일>" [--file ...] --note "<무엇이 왜 붙었는지>" --yes
```

| 규칙 | 왜 |
| --- | --- |
| **폴더는 항목별로 압축한다** | 통째로 한 덩어리면 용량 제한에 걸리고, 받는 사람이 필요한 것만 가져갈 수 없다. 배포본 / Generate 결과 / 평가 산출물을 따로 |
| **본문이 직접 인용하는 단일 파일은 압축하지 않는다** | 클릭해서 바로 열려야 근거 구실을 한다 (대조표·빌드 로그 등) |
| **압축본은 스크래치패드에 만든다** | 넘겨받은 폴더를 건드리지 않는다 |
| **`--note` 에 무엇이 왜 붙었는지 적는다** | 파일명만으로는 §6 의 어느 줄에 해당하는지 모른다 |
| **묻지 않고 그 자리에서 올린다** | 사용자 방침(2026-11-06). 본문 §6 에 적은 자료를 붙이는 일이라 **본문 전송 승인에 포함된다.** 본문을 보냈으면 이어서 `--yes` 로 올리고, 무엇을 몇 MB 올렸는지는 **끝난 뒤에 보고**한다 |
| 본문 §6 에 없는 자료를 붙이려면 | 그건 새 결정이다. 그때는 묻는다 |
| **첨부는 지우지 않는다** | 지우는 것은 사람이 화면에서 한다 |
| 암호 걸린 배포본 zip **원본은 올리지 않는다** | 암호가 메일에 있어 받는 사람이 열지 못한다. 전개본을 다시 압축해 올린다 |
| 용량이 거부되면(`413`/`422`) | 사유를 그대로 보여 주고 **쪼개는 방법을 제안한다**. 조용히 빼지 않는다 |

본문 §6 과 첨부 목록이 **서로 가리켜야** 한다. §6 에 적힌 자료가 첨부에 없거나, 첨부에만
있고 §6 이 설명하지 않으면 작업자가 무엇을 받았는지 모른다.

실제 예 (#49949, 2026-11-06) — 배포본 27.5MB→9.8MB, Generate 결과 26.8MB→1.7MB 로 압축하고
대조표·BswM arxml·빌드 로그 3개는 그대로, 합계 5개 13.6MB.

## 4. 멈춰야 할 때

| 상황 | 하는 일 |
| --- | --- |
| 버전이 페이지와 manifest 에서 다르다 | 멈추고 양쪽 값을 보여 준다 |
| 중첩 압축을 찾았다 | 전개 여부를 묻는다 (자동 전개하지 않는다) |
| 같은 회차 일감이 **ASEC 에** 이미 있다 | 중복이다. 새로 만들지 말고 수정·코멘트를 제안한다 |
| 담당자·마감일이 정해지지 않았다 | **비워 둔다.** 사용자가 말하지 않으면 넣지 않는다 |
| 차량단계를 모른다 | **묻지 말고 프로필에서 가져온다**(페이지 §1 의 제어기 단계가 근거다). 프로필에도 없으면 `N/A` 를 쓴다. **필수 필드라 비우면 422 이므로 비워 둘 수는 없다** |
| 첨부가 용량으로 거부됐다 | 쪼개는 방법을 제안한다. 조용히 빼지 않는다 |
| 남이 등록한 일감을 고쳐 달라 | 직접 쓰지 않는다. 코멘트 초안을 만들어 사용자가 올린다 |

## 5. 이어서 관리하기

| 일 | 어떻게 |
| --- | --- |
| 짝 구분(FBL↔APP)이 나중에 왔다 | **구분마다 일감을 따로 만든다.** 그리고 서로 번호를 걸어 둔다 — 한쪽에 생긴 결론이 다른 쪽에 영향을 주면 그때 그 일감을 `update` 로 갱신한다. ASEC 일감은 내가 등록자라 수정이 된다 |
| 한 일감에 두 구분을 묶어 달라고 한다 | #48891 처럼 제목에 `[FBL][V<x>][APP][V<y>]` 를 함께 쓰는 선례가 있다. **사용자가 그렇게 요청할 때만** 묶는다. 기본은 따로다 |
| 회차가 추가됐다 | 회차마다 일감을 새로 만들고 적용 건 일감(`<차종><제어기> SWP 모듈 패치 적용 건`)에 줄을 더한다 |
| 작업이 끝났다 | 결과 코멘트. 양식은 `../swp-delivery-patch/references/templates.md` §2 |
| 리뷰어가 지적했다 | 항목별 처리 → 번호별 회신. 같은 파일 §2-1 |
