# joule-tc

제어기 평가 TC 의 **정본을 손보는** 스킬이다. 돌리는 것이 아니라 **무엇을 돌릴지 정하고 그 근거를 적는** 일이다.

| 하려는 일 | 명령 | 절차 |
|---|---|---|
| 이번 회차에 돌릴 TC 고르기 | `select` | A |
| 사람이 할 일 넘기기 | `manual` | B |
| TC 추가·수정 | `gen` · `check` · `list` | C |
| 제어기 추가 | `rxvars` · `gen` | D |
| 설정 항목에 결말이 있는가 | `coverage` | E |

실행은 `uv run --directory <Joule> joule-tc <하위 명령> <제어기>` 다 (작업 폴더를 옮기지 않는다).
`<Joule>` 은 환경변수 `JOULE_HOME`, 없으면 `D:\Mobase\asec_autotest_tool` 이다.

## 먼저 읽는다

1. **정본은 저장소 문서다** - `docs/joule-tc-catalog.md`. 2절(결말 넷·메우는 틀) · 7절(빈 곳) ·
   9절(단계와 완료 조건) · 11절(위험한 자리)를 손대는 일에 맞게 읽는다.
2. `uv run --directory <Joule> joule-tc <하위 명령> --help`.
3. **이 스킬과 저장소 문서가 다르면 저장소 문서가 맞다.** 옵션·칸 이름·판정 기준을 이 스킬에 복제하지 않는다.

## 절대 규칙

- **`configs/tc/` 를 손으로 고치지 않는다.** 생성물이고 다음 `gen` 이 파일을 통째로 덮어쓴다.
  고칠 자리는 `configs/tc_catalog/<모듈>.toml`(공통) 과 `configs/tc_profiles/<제어기>.toml`(제어기 고유값)이다.
- **카탈로그를 고치면 제어기 넷을 다 `gen` 하고 `check` 한다** (`he1i_psu_drv`·`nq6e_psu_drv`·`nq6e_apsu`·`tpms_rf_lt2`).
  한 제어기만 하면 나머지가 어긋난 채로 남는다.
- **모르는 값을 추정해서 채우지 않는다.** 프로파일 칸을 비우면 그 TC 는 건너뛰어지고 **까닭이 찍힌다** -
  그것이 바른 결과다. 추정한 시간 창·DID·주소는 엉뚱한 판정을 만든다.
- **커버리지가 거짓말하지 않게 한다.** 열거 항목의 결말은 넷이다 - TC 가 덮는다(`params`) / 확인 불가 /
  설정 구조 / **빠짐**. 셋째 쪽으로 밀어 넣어 숫자를 올리지 않는다 (절차 E).
- **보드에 보내는 일은 이 스킬에 없다.** TC 를 만들었으면 실행은 can-bench-setup 으로 넘긴다.
- **저장소 파일을 고치면 바뀌는 내용을 보여 주고 확인받는다.** 커밋·푸시는 사용자 확인 뒤에만 한다.
- **테스트는 좁게.** 고치는 동안과 커밋까지는 덮는 파일만 (`uv run --directory <Joule> pytest tests/test_tc_catalog.py tests/test_tc_golden.py -q`).
  전체(약 4분)는 푸시 직전 한 번이다.
- 한국어로 보고한다. 화면·로그 문자열에 cp949 에 없는 문자를 쓰지 않는다.

## A. 이번 회차에 돌릴 TC 고르기

1. **바뀐 모듈을 가린다.** 근거는 패치 쪽 자료(`patch_manifest`·릴리즈 노트)와
   제어기 프로젝트의 `Configuration/Ecu/Ecud_<모듈>.arxml` 변경, DB import 버전이다. 짐작하지 않는다.
2. `joule-tc select <제어기> --modules Dcm,NvM` - 트리거 정본은 `configs/tc_catalog/_triggers.toml` 이다.
   넓어지는 길이 넷이다 (그 모듈 / `modules` 로 걸치는 TC / 규칙의 `tabs`·`tcs`·`also` / 규칙 `all`).
3. 출력에서 **그냥 지나치면 안 되는 것 넷**이다.
   - `생략 가능 후보` - **빼지 않고 표시만 한다. 사람이 결정한다.**
   - `TC 가 아니라 이 명령이 본다` - 기본 검증(`joule-verify basic`)·리프로그래밍(`joule-reprog`) 몫.
   - `아직 TC 가 없다 - 사람이 손으로 본다` - 7절 빈 곳.
   - 규칙 메모(왜 이 탭이 들어왔나). 이름을 전부 보려면 `--tcs`, 넓혀도 TC 가 없는 모듈 이름은 `--left`.
4. 계획 파일(`configs/plans/<제어기>.toml`)에 넣을 줄은 `--names` 가 찍는다. **도구가 그 파일을 고치지 않는다** -
   사람이 붙인다. `manual`·`skip` 줄을 지우지 않고 그대로 가져간다.
5. 돌리는 것은 can-bench-setup 이다 (`joule-run <제어기>`).

## B. 사람이 할 일 넘기기

- `joule-tc manual <제어기>` - 요구하는 것으로 가른 안내서가 나온다 (**사람 손** / **디버거** / **전원 제어**).
  TC 하나만 보려면 `--tc <id>`.
- **`manual = true` 가 곧 사람이 필요하다는 뜻이 아니다.** 디버거 감시(계획에 `cvd_watch = true`)와
  릴레이 박스가 있으면 무인이 된다. 안내서가 "무엇을 갖추면 무인이 되나" 를 함께 찍는다.
- 사람 손 묶음은 절차와 판정까지 찍히므로 **그 글을 그대로 사용자에게 넘긴다** (옮겨 적지 않는다).

## C. TC 추가·수정

1. `joule-tc list` 로 어느 모듈 파일인가 고른다. 축은 **모듈**이다 (AUTOSAR 모듈 이름 - 옛 "영역" 이 아니다).
2. 그 모듈 파일에 `[[tc]]` 를 더한다. 먼저 **같은 파일의 이웃 TC 를 읽고 그 모양을 따른다.**
   `basis` 에는 **설정 근거**(`Ecud_<모듈>.arxml` 의 어느 파라미터인지)를 적고, `params` 에는 그 파라미터 이름을 적는다.
3. 제어기마다 다른 값은 프로파일로 뺀다. **설명 글은 치환하지 않는다** - TC TOML 은 사람이 읽는 문서이기도 하다
   (11절). 치환은 메시지 이름·주소·시간 창·DID 목록처럼 **제어기마다 반드시 다른 값만** 한다.
4. `gen` 넷 → `check` 넷 → 좁은 테스트.
5. **골든이 떨어지면 TC 의 뜻이 바뀐 것이다** (주석·순서는 통과한다). 의도한 변경이면
   `JOULE_GOLDEN_UPDATE=1 pytest tests/test_tc_golden.py` 로 다시 뜨고 **바뀐 내용을 커밋에서 보인다.**
   의도하지 않았으면 멈추고 사용자에게 알린다 - 실기로 통과한 자산이 조용히 달라지는 것을 막는 못이다.
6. **문서도 같이 고친다** (`docs/joule-tc-catalog.md`). 새로 알게 된 사실은 CLAUDE.md 가 아니라 docs 로 간다.
7. 새로 만든 TC 는 **실기 전**이다. 그렇게 보고한다 (9절 8단계 - 실기는 can-bench-setup).

## D. 제어기 추가

1. 제어기 설정(`configs/ecus/<제어기>.toml`)이 먼저 있어야 한다 - 없으면 `joule-ecu-project` 쪽 일이다.
2. `joule-tc rxvars <제어기>` - 수신 메시지 표를 제어기 프로젝트에서 뽑는다.
   `configs/ecus/rxvars/<제어기>.toml` 은 **생성물**이고, 빌드가 바뀌면 다시 돌린 뒤 `gen` 을 돌린다.
3. 프로파일(`configs/tc_profiles/<제어기>.toml`)을 쓴다. 이웃 제어기 파일을 보고 칸을 맞추고,
   **모르는 칸은 비워 둔다** (그 TC 가 건너뛰어지고 까닭이 찍힌다).
4. `gen` → `check` → 좁은 테스트. 건너뛴 TC 목록을 사용자에게 그대로 보인다.

## E. 커버리지 메우기 - 설정 항목에 결말이 있는가

`joule-tc coverage <제어기> [--area <모듈>]`. 분모는 카탈로그 머리말이 아니라 **`Ecud_<모듈>.arxml` 재열거**다 -
그래서 패치로 설정 항목이 늘면 빠짐으로 드러난다. 나무를 따로 줘야 하는 제어기는 `--project <경로>` 다.

빠짐을 셋으로 가른다 (틀의 실례는 docs 2절 - `CanNm`·`Dcm`·`Nm`·`ComM`).

| 갈래 | 하는 일 |
|---|---|
| **있는 TC 가 이미 덮는다** | 그 TC 의 `params` 에 이름을 적는다 |
| **열거 분류** | `[[unobservable]]`(왜 볼 수 없나) · `[[structural]]`(어느 TC 가 효과를 보나) 에 **까닭과 함께** |
| **아직 TC 가 없다** | **빠짐으로 남긴다.** 모듈 파일 머리의 "아직 생성하지 않는 TC" 에 그 이름을 적는다 |

이 셋을 가릴 때의 규칙이다.

- **설정 값을 보고 가린다.** 이름으로 짐작하면 거꾸로 적는다 - 값이 적혀 있어도 그 서비스가 꺼져 있어
  닿지 못하면 확인 불가이고, 꺼진 항목이라도 **그 거절을 보는 TC 가 있으면** 덮인 것이다.
- **계획 TC 가 적혀 있는 항목은 확인 불가로 옮기지 않는다.** 겨눌 TC 를 적어 둔 것은
  "못 본다" 가 아니라 "아직 안 만들었다" 다.
- **`params` 는 모듈을 가리지 않는다.** 다른 모듈 TC 가 덮으면 그 TC 에 적고, **그 TC 의 `modules` 에도
  그 모듈을 더한다** (`select` 가 고르게 된다). `modules` 가 바뀌면 생성물 주석이 바뀌므로 `gen` 을 다시 돌린다.
- 카탈로그에 "계획" 칸을 **새로 만들지 않는다.** 만들지 않은 TC 가 결말로 세어지면 커버리지가 거짓말을 한다.
- 커버리지 100% 는 **"항목마다 결말이 적혀 있다"** 는 뜻이고 "TC 로 다 돌려 봤다" 가 아니다. 그렇게 보고한다.
- 빠짐이 있으면 종료 코드 1 로 떨어뜨리려면 `--strict` 다 (닫힌 모듈이 다시 열리는 것을 막는 자리).

## 범위 밖

- 버스로 보내고 판정하는 실행 - `can-bench-setup` (`joule-verify`·`joule-run`)
- 보드에 쓰기·플래시 대조 - `cvd-project` (`joule-flash`)
- 리프로그래밍·H-OTA - `hota` · `hota-tester` (`joule-reprog`·`joule-hota`)
- 제어기 프로젝트 조사와 제어기 설정 초안 - Joule `joule-ecu-project`
- 판정 기준·단계 종류를 새로 만드는 일은 Joule 코드 쪽이다. 필요해지면 **7절 "빈 곳"** 에 적고 멈춘다.
