# Confluence Cross-Site Copy

서로 다른 Confluence 인스턴스 사이에서 페이지(또는 폴더) 트리를 복사한다.

**핵심 전제**: 읽기와 쓰기의 가능 경로가 다르다. 이 비대칭 때문에 **복사를 시작하기 전에 경로 판정을 반드시 먼저 한다.**

| | 읽기 | 쓰기 |
| --- | --- | --- |
| MCP 승인된 사이트 | ⭕ `getConfluencePage` | ⭕ `createConfluencePage` |
| MCP 미승인 사이트 | ⭕ 브라우저 REST (`?expand=body.storage`) | ⭕ 브라우저 클립보드 자동화 (경로 C) |

> ⭐ **경로 C(클립보드)가 서식 충실도가 더 높다.** 같은 Confluence끼리는 에디터 클립보드가 내부 문서 포맷을 그대로 실어 나르므로 패널·형광펜·코드블록이 번역 없이 넘어간다. 그리고 **첨부 이미지(SVG·PNG)도 경로 C에서는 자동 복원된다** — "첨부는 사용자가 직접"이라는 옛 전제는 틀렸다. `references/clipboard-automation.md` §5.

---

## 1단계 — 경로 판정 (가장 먼저, 예외 없음)

```
getAccessibleAtlassianResources 호출
  ├ 타겟 사이트가 목록에 있나?
  │    있음 → 쓰기: MCP (경로 A/B로 읽어 변환 후 발행) — 단, 첨부가 있으면 경로 C 권장
  │    없음 → 쓰기: 브라우저 클립보드 (경로 C) — 중단하지 않는다
  └ 소스 사이트가 목록에 있나?
       있음 → 읽기: MCP (하위 트리는 getConfluencePageDescendants depth 5~10)
       없음 → 읽기: 브라우저 (references/access-routing.md)
```

토큰은 **계정 하나** 기준이며 그 계정이 멤버인 사이트만 뜬다. 회사 계정(예: jdlee@mobaseasec.com)으로 인증돼 있으면 개인 사이트는 안 보이는 것이 정상이고, 커넥터를 개인 계정으로 재연결하면 반대로 회사 사이트가 사라진다. 양쪽을 MCP로 보려면 한 계정이 양쪽 멤버여야 한다(개인 사이트에 회사 계정 초대 — 관리형 계정이면 회사가 통제한다는 점만 알리고 판단은 사용자 몫). 사용자가 "ljindong도 MCP 되나요?"라고 물으면 이 구조를 설명하고, 안 하겠다고 하면 경로 C로 그대로 간다.

- URL 형태: 페이지 `…/pages/<pageId>/<슬러그>`, 폴더 `…/folder/<folderId>`. **URL 슬러그는 제목이 아니다** — 실제 제목은 API·`document.title`로 읽는다.
- 소스가 **폴더**면 `getConfluencePageDescendants`는 404다. `searchConfluenceUsingCql`로 `parent = <folderId> AND type = page`를 조회해 직계를 얻고, 각 페이지에 descendants를 건다.
- 브라우저를 쓰기 전에 이유를 설명하고 승인을 받는다. Claude in Chrome 연결 브라우저가 둘 이상이면 **사용자가 고른다**(다른 PC를 골랐다 끊긴 사고가 있었다).

## 2단계 — 대화형 수집

1. **소스 URL / 타겟 URL** — 재확인
2. **경로 판정 결과 보고** — 읽기/쓰기 경로, 타겟 폴더·페이지의 현재 상태
3. **하위 트리 제시** — 전체 트리를 표로(제목·원본 ID·하위 수·이미지 수). 빈 껍데기 페이지는 표시한다
4. **범위·제외 질문** — 전체 / 직계만 / 골라서. "부록 — 당사 적용 현황"처럼 사내 특화 페이지는 제외 선택지로 따로 보여준다
5. **발행 확인 방식 질문** — 기본은 페이지마다 확인이지만, 페이지가 10개를 넘으면 "검증 후 자동 발행"을 선택지로 준다. 사용자가 한 번 승인하면 이후는 검증 결과만 보고하고 발행한다
6. **제목 충돌 사전 검사** — Confluence는 **스페이스 전체에서 제목이 고유**하다. 옮길 제목 전부를 타겟 스페이스에서 미리 조회해(`/wiki/rest/api/content?spaceKey&title`) 충돌을 알리고 접미어 규칙을 정한다(예: `타입 힌트 (python-dev)`)

**트리 구조 원칙** — 소스 URL이 가리키는 것 자체가 복사의 루트다:
- 소스가 **페이지** → 타겟 부모 아래에 **그 페이지를 먼저 만들고** 하위를 그 아래에
- 소스가 **폴더** → 타겟 부모 아래에 **같은 이름의 폴더를 먼저 만들고** 그 안에 (폴더를 빼먹고 내용물만 쏟은 사고가 있었다. 뒤늦게 발견하면 폴더를 만들고 move API로 옮긴다 — `clipboard-automation.md` §4)

## 3단계 — 실행

### 3.A MCP 쓰기

```
1. 타겟 부모의 spaceId·pageId 확보
2. 소스 루트 읽기 → 변환(4단계) → create (타겟 부모 아래)
3. 하위를 위에서 아래로: 읽기 → 변환 → create (parentId = 부모의 새 ID)
4. 매 페이지 "N/총 제목 → 새 ID" 보고, 실패 시 즉시 중단·보고
```
읽기 → 변환 → 발행을 **페이지 단위로** 이어서 한다. 전부 읽어 쌓아두면 컨텍스트가 터진다. 기존 타겟 페이지를 채우는 경우는 update이므로 별도 허락 + 직전 fetch(`confluence-writing` §4).

### 3.C 클립보드 쓰기 (경로 C) — `references/clipboard-automation.md`가 정본

페이지 하나당 약 40초의 고정 루틴이다. **스크립트는 그 문서의 것을 그대로 쓴다**(검증된 선택자·대기·검증식).

```
소스 탭: navigate(보기 화면) → 본문 전체 선택·메타 수집 → ctrl+c
타겟 탭: navigate(create-content/page?spaceKey&parentPageId) → 제목 입력 → 본문 ctrl+v
         → ProseMirror 문서 모델로 검증(글자수·표·코드·목록·끝문장)
         → '게시…' → 다이얼로그 '게시' → URL이 /pages/<새ID>/로 바뀌면 완료
```

- 소스는 보기 화면만 쓴다. 편집 모드로 들어가야 하면 저장 없이 나온다.
- 검증이 어긋나면 발행하지 않고 원인(클립보드 비움·제목 중복·부분 붙여넣기)을 본다.
- 트리는 루트 → 1단계 → 2단계 순, `원본ID → 새ID` 표를 유지한다.
- 모든 페이지 발행 후 **첨부 복원**(§5)과 **구조 검증**(descendants API)을 하고, 페이지 수는 API로 세어 보고한다.

---

## 4단계 — 변환 (MCP 쓰기일 때만)

저장 포맷(storage XHTML)과 MCP HTML은 다른 형식이다. **발행 전 `references/storage-to-html.md`를 읽는다.** 자주 걸리는 세 가지: 코드 매크로 → `<pre><code class="language-…">`, `<colgroup>` → `data-colwidth`, 형광펜(`background-color`) → 굵게(그대로 넣으면 글자가 사라진다). 헤더 레벨은 원본 그대로.

경로 C에서는 변환이 없다. 제목의 `&amp;` 오표기만 `&`로 바로잡고 보고한다.

---

## 5단계 — 첨부 복원 (경로 C)

본문에 쓰인 이미지는 붙여넣기 직후 `ri:filename="Invalid file id - …"`로 깨져 있다. 소스 탭에서 파일을 읽어(SVG는 텍스트, PNG는 base64) JSON으로 묶어 클립보드로 넘기고, 타겟의 **"첨부 파일" 화면 폼**으로 업로드한 뒤 본문 참조를 파일명으로 바꿔 저장한다(페이지 v+1). REST 업로드는 XSRF로 막히므로 폼이 유일한 길이다. 절차·스크립트·주의(파일 매크로는 건드리지 않기)는 `clipboard-automation.md` §5.

- 대상은 **본문의 `<ac:image>`에 쓰인 파일만**. `.skill`·PDF·exe 같은 자료 첨부는 제외하고 완료 보고에 목록으로 남긴다.
- 끝나면 트리 전체에서 `Invalid file id` 0건을 확인한다.
- MCP 쓰기 경로에는 업로드 수단이 없다 — 첨부가 많으면 처음부터 경로 C를 권한다.

## 6단계 — 완료 보고

1. **생성된 페이지 표** — 트리 모양대로, 원본 ID → 새 ID (수는 API로 센 값)
2. **첨부 복원 결과** — 페이지·파일·크기 일치 여부, 제외한 자료 첨부 목록
3. **제외된 페이지와 이유**
4. **원본과 달라진 점** — 제목 접미어·`&amp;` 정정·형광펜 대체 등 손댄 것 전부
5. **사용자가 직접 할 일** — 소스 사이트를 가리키는 내부 링크(새 ID로 치환 권고), 자료 첨부, 트리 정렬 순서
6. 발행 중 생긴 부작용(잘못 바꿨다 되돌린 버전 등)도 숨기지 않는다

## 🚫 사고 방지 규칙

1. **경로 판정이 먼저.** 승인 여부에 따라 선택지가 달라진다.
2. **소스 URL이 폴더면 타겟에도 폴더부터.** 내용물만 쏟지 않는다.
3. **경로 C 발행은 사용자 확인 또는 사용자가 준 일괄 승인 아래서만.** 검증 실패 상태로는 누르지 않는다.
4. **기존 페이지 수정은 별도 허락 + 직전 fetch.** (`confluence-writing` §4)
5. **첨부 참조 교체는 `<ac:image>`만.** 파일 매크로까지 덮어쓰면 자료 링크가 망가진다.
6. **소스를 수정하지 않는다.** 읽기 전용.
7. **같은 사이트 안 복사에는 쓰지 않는다.**
8. 브라우저 접근 거부·탭 그룹 소실 시 재시도하지 말고 상태를 보고한 뒤 지시를 기다린다. 발행 안 된 초안은 `edit-v2/<id>`로 이어 쓴다.
9. **중간 보고를 거르지 않는다.** 페이지마다 한 줄, 묶음마다 요약.
