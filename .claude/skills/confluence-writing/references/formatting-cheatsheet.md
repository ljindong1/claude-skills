# 서식·시각화 치트시트

Confluence 본문 표현 규약. contentFormat 선택·발행 메커니즘은 confluence-ops.md 담당.

---

## 1. 박스 강조 — blockquote + 이모지 헤더 (ADF panel 대체)

markdown에서 panel은 표현 불가. blockquote + 이모지 헤더 + 굵은글씨로 대체한다 (Confluence에서 회색 좌측 막대로 렌더링 — 강조 충분).

| 기존 ADF panel | 대체 패턴 | 용도 |
| --- | --- | --- |
| panel-info (파랑) | `> 📌 **제목**` | 참고 자료, 추가 정보 |
| panel-warning (노랑) | `> ⚠️ **주의**` | 보안·컴플라이언스 주의, 사전 경고 |
| panel-note (회색) | `> 💡 **핵심**` | 핵심 통찰, 필독 강조 |
| panel-success (초록) | `> ✅ **권장**` | 권장 패턴, 성공 사례 |
| panel-error (빨강) | `> 🚫 **절대 금지**` | 사고 위험 — 일상적 주의에 남용 금지 |

규칙: 페이지당 4개 이내. 첫 줄은 `> [이모지] **헤더**`, 본문은 빈 `>` 한 줄 뒤부터. blockquote 안에서 리스트·코드·강조 사용 가능 (각 줄 앞 `> `).

## 2. 표 규약 ⭐ (본 스킬 최다 사용 컴포넌트)

### 2.1 내용 규칙

```markdown
| 항목 | 설명 | 비유 / 매핑 |
| --- | --- | --- |
| **[항목명]** | [설명] | [그 분야의 비유] |
```

- 헤더 행 모든 셀 `**...**` 굵게 (키 컬럼과 겹쳐도 일관성 우선).
- 첫 컬럼은 항상 키 항목 (이름/단계/카테고리), `**...**` 굵게.
- 3~4 컬럼 권장, 5 이상 금지 (분할).
- 비유/매핑 컬럼 추가 시 학습 효과 ↑.
- 상태 마커로 빠른 스캔: ⭕ 권장/가능 · ❌ 금지/불가 · ⚠️ 주의 · ⭐ 핵심 · ◯ 선택 · △ 조건부.
- 셀 내 줄바꿈은 `<br>` (안 되면 분할).

### 2.2 ⭐ 컬럼 폭 배분 — data-colwidth (2026-07 갱신)

GFM 표에는 폭 문법이 없어 균등 분배로 렌더링된다. **내용에 맞는 폭이 필요한 표가 하나라도 있는 페이지는 `contentFormat: "html"`로 작성**하되 (confluence-ops §2), **`<colgroup>`을 직접 쓰지 않는다** — create/update 모두 저장 시 서버가 제거해 균등 폭으로 렌더링된다.

대신 **모든 행의 모든 셀에 `data-colwidth="N"`**을, `<table>`에 `data-layout="default" data-display-mode="fixed"`를 지정한다:

```html
<table data-layout="default" data-display-mode="fixed">
  <thead><tr>
    <th data-colwidth="140"><p><strong>항목</strong></p></th>
    <th data-colwidth="460"><p><strong>설명</strong></p></th>
    <th data-colwidth="160"><p><strong>비유</strong></p></th>
  </tr></thead>
  <tbody><tr>
    <td data-colwidth="140"><p>...</p></td>
    <td data-colwidth="460"><p>...</p></td>
    <td data-colwidth="160"><p>...</p></td>
  </tr></tbody>
</table>
```

**폭 배분 휴리스틱** (전체 기준 폭 760px — Confluence 본문 기본):

| 컬럼 역할 | 배분 |
| --- | --- |
| 마커/상태 컬럼 (⭕❌⭐, "중요도") | 최소폭 ~80px 고정 |
| 키 컬럼 (이름/단계) | 그 컬럼 최장 셀 기준 15~25% |
| 설명/내용 컬럼 | 잔여 폭 최대 배분 |
| 보조 컬럼 (비유, 비고) | 잔여의 25~35% |

> 📌 **검증 이력**: 2026-07-13 mobaseasec 실측 — `data-colwidth` 방식은 저장 시 서버가 `<colgroup><col style="width: N.0px;"/>` + `data-table-display-mode="fixed"`로 변환·보존해 지정 폭으로 렌더링됨을 확인. `<colgroup>` 직접 작성은 저장 시 제거됨(균등 폭 렌더링)을 확인. ISO 26262 가이드(대표 268861441) 8개 페이지 17개 표에 적용 완료.

## 3. 상태 표시 (Status Lozenge 대체)

| 기존 ADF | 대체 | 예시 |
| --- | --- | --- |
| green | 이모지 + 텍스트 | ✅ 완료 |
| red | 이모지 + 굵게 | 🚫 차단, ❌ **BLOCKED** |
| yellow | 이모지 + 텍스트 | 🟡 진행 중, ⚠️ **WIP** |
| blue / purple | 이모지 + 텍스트 | 🔵 정보 / 🟣 검토 |

## 4. 코드 블록·인라인 강조

- fenced code block + 언어 식별자: `bash` `powershell` `c` `cpp` `python` `javascript` `typescript` `yaml` `json` `toml` `xml`(ARXML/DBC) `sql` `dockerfile`.
- 명령어는 항상 코드 블록. 인라인 `` ` ``은 변수명·짧은 식별자만.
- 코드 블록 위에 무엇을 하는 코드인지 한 줄 명시.
- ASCII 다이어그램도 코드 블록 (언어 식별자 없이).
- 코드 예시 언어는 분야 매트릭스(writing-style §4.2)를 따른다.

인라인 강조: 핵심 키워드 `**...**` / 경로·식별자 `` `...` `` / 요점 `> **결론**: ...` / 부드러운 강조 `*...*`.

### 4.1 굵게(`**`)가 그대로 노출될 때 — 회피 규칙

- `**` 안쪽 공백 금지: ⭕ `**비동기**` / ❌ `** 비동기 **`
- 한글에 공백 없이 붙이지 않기 (Confluence 파서의 CJK boundary 한계): ⭕ `이 **비동기** 함수는` , `**비동기**다.` / ❌ `이것은**비동기**함수다.`
- `**` 사이에 단락 경계(빈 줄) 금지, 한 줄 내 짝수 개 유지.
- `**` 안에 백틱·이탤릭 중첩 금지 — 굵게+코드 필요 시 코드만.
- 복붙 시 `\**` 이스케이프 잔재 확인.

금지: `<span style="color:red">` 색상 직접 지정 (markdown 모드에서 escape됨).

## 5. 시각화 표현 ⭐

시각화는 1순위 표현 수단. 다음이 등장하면 **다이어그램 필수**: 시스템 구성/아키텍처, 컴포넌트 연결·의존성, 데이터/신호 흐름, 계층/트리, 상태 전이, 추상 개념의 비유적 시각화, 분류 매트릭스.

빈도: 대표 페이지 전체 구조도 1개 **필수** / 하위 페이지당 1~2개 권장 / 단순 명령 나열·짧은 노트만 생략 가능.

### 5.1 형식 선택

| 표현 대상 | 종류 | 형식 |
| --- | --- | --- |
| 시스템 구조/배치, 연결·의존성, 흐름, 타임라인 | 구조도/흐름도 | ASCII 또는 SVG 파일 |
| 상태 전이, 추상 개념 일러스트 | 상태도/일러스트 | SVG 파일 (ASCII 한계) |
| 분류/비교 매트릭스 | 매트릭스 | GFM 표 |

- **단순/중간 → ASCII 다이어그램** (즉시 포함, 사용자 작업 0): 코드 블록 안 `┌─┐ │ →` 텍스트 도형. 색상 불가, 6개+ 박스·곡선 화살표 한계.
- **복잡/색상 중요 → SVG 파일** (사용자 드래그앤드롭 첨부 — 메커니즘은 confluence-ops §5).

페이지별: 대표=SVG 권장 / 개념 설명=ASCII 또는 SVG / Q&A=표 또는 ASCII / 튜토리얼=ASCII / 구성도 페이지=SVG (주인공).

### 5.2 다이어그램 + 설명 블록 표준 패턴 (항상 동반)

```
[다이어그램 — ASCII / 표 / SVG 자리]

#### 색상의 의미
- 회색 — [의미] ...
#### 화살표가 말하는 것
- 위에서 아래로 — [의미] / 점선 — [의미]
#### 이 그림의 핵심 통찰 ⭐
1. [이 그림에서 무엇을 깨달아야 하는가 — 1~3개]
```

이 블록 덕분에 SVG 첨부가 미뤄져도 텍스트만으로 핵심이 전달된다.

### 5.3 SVG 작성 원칙

**`svg-creation` 스킬을 먼저 활성화** (viewBox-only, 한글 폰트 스택 `'Apple SD Gothic Neo','Malgun Gothic','Noto Sans CJK KR',...`). 그 위에 Confluence 고유 규칙:

- viewBox 폭 680 기준 (`viewBox="0 0 680 400"`), `width`/`height` 지정 금지 (일부 매크로에서 0px로 사라짐).
- 색상은 의미 인코딩: 회색=중립/구조, 파랑=실행 주체, 노랑=설정/저장소, 청록=외부 도구, 보라=클라우드/원격, 산호=보조. 2~3색 제한 (6색+ 금지), 색만으로 의미 표현 금지 (라벨/형태 동반).
- 글자 14px 이상. 분야별 매핑 라벨 "(= 친숙한 개념)". 색상·화살표 범례를 SVG 안에 포함.
- `xmlns="http://www.w3.org/2000/svg"` 필수. 그라데이션·그림자 금지.

## 6. markdown에서 표현 불가한 ADF 요소 — 대체 요약

| 잃는 요소 | 대체 |
| --- | --- |
| panel 5종 | blockquote + 이모지 (§1) |
| status lozenge | 이모지 + 텍스트 (§3) |
| 2/3 컬럼 레이아웃 | 표 또는 H3 섹션 분할 |
| expand/collapse | 헤더 + 본문 평탄화 (`<details>`도 escape됨) |
| 인라인 카드 | 일반 링크 `[제목](URL)` |
| 멘션 / 날짜 위젯 | 텍스트 `@이름` / `2026-05-11` |
| `<svg>` 인라인 | ASCII 또는 SVG 파일 첨부 (confluence-ops §5) |

## 7. 헤딩 위계 ⚠️ — 본문 H1·H2 금지

Confluence는 `title` 파라미터를 자동으로 H1 렌더링한다.

```
#   → ❌ (title과 중복)      ##  → ❌ (시각적으로 너무 큼)
### → ⭕ 본문 최상위 (시작점)   #### ⭕ 절   ##### ⭕ 소절
```

본문 첫 요소는 항상 **일반 단락**. 기울임꼴(`*...*`) 리드 문단은 쓰지 않는다 — 사용자 비선호로 2026-07 폐기. 모든 페이지 종류에 예외 없음.
